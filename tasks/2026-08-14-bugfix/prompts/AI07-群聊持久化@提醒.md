## 当前真正缺口

“last message 是否 mention 我”不能代表未读 @：

- 后面又来了普通消息会覆盖 lastMessage。
- App 重启后内存 notice 消失。
- WebSocket 漏事件后不能恢复。
- 多设备同步会不一致。

所以必须有 durable viewer-specific unread mention summary。

## Conversation/API 契约

对当前 principal 的 group conversation summary 增加稳定字段，名字自定但语义必须清楚，例如：

- latestUnreadMentionMessageId
- latestUnreadMentionSequence
- unreadMentionCount（可选）

判定基于：

- 当前用户是 active member。
- mention sequence > 当前 member last_read_sequence。
- message 未 recalled。
- direct mention userId 匹配当前 user，或有效 `MENTION_ALL`。

不得返回其他用户的 mention 状态。

## `MENTION_ALL` 边界

- 继续复用现有 server authorization；普通成员不能靠构造文本绕过 @all 权限。
- sender 自己不应被自己的 @all 标成“有人@你”。
- 已离群/被移除后的历史行为按当前消息可见性/成员状态规则处理，必须写测试。

## Mark read

利用现有 `last_read_sequence`，不要再造第二套“已读 mention boolean”状态机：

- 当 read sequence >= latest mention sequence，未读 @ 自然消失。
- 如果用户只点击 @ 提醒定位消息但没有真正更新 read，按现有阅读语义决定；不要偷偷将整个会话标读而破坏 unread count。
