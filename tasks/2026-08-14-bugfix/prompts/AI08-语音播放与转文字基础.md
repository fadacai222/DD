## 已确认的播放延迟原因

当前 `_toggleVoicePlayback()` 会先完整等待 `_mediaBytesFor(mediaId)`，之后才设置 playing state 并调用 player。cache miss 时，下载时间直接变成“点击无反应”的时间。

已有：

- `ChatVoicePlayer`
- Windows `media_kit`
- 其他平台 `audioplayers`
- coordinator `isVoiceHeard()` / `markVoiceHeard()` 持久状态

## Part A：真正改善首播响应

1. 把 voice player 输入抽象成 source，至少支持：
   - cached local file path；
   - 有授权的短期 HTTPS media URL；
   - bytes 仅作为必要 fallback。
2. cache hit 优先本地路径。
3. cache miss 优先尝试流式 URL 播放，并可后台缓存；如果某平台底层不稳定，再使用有界预取。
4. 用户点击后立即进入 `starting/loading` 状态，不等媒体完整下载。
5. 失败要恢复 idle 并向 UI 提供稳定错误事件。
6. 只预取近期/可见/下一候选语音，限制并发与大小；禁止下载整个历史。
7. 授权 URL 过期时最多按现有 grant 机制合理刷新，不能死循环。
8. 不能绕过现有 media authorization。

## Part B：首次未听红点

直接复用 heard state：

- 对方 VOICE + `!isVoiceHeard(message.id)` = unread voice。
- 自己发送的 VOICE 不显示未听红点。
- 只有音频**真正开始播放**后才 mark heard。
- 预取完成、点击失败都不能提前消红点。

请提供独立 selector/state，最终红点 Widget 由总负责人接入。

## Part C：连续播放状态机

不要实现“进入聊天页面自动外放”。产品语义固定为：

> 用户主动点击第一条未听远端语音后，播放完成可顺序播放同一会话后续符合条件的未听 VOICE。

以下情况立即中断连播：

- 用户手动暂停/停止；
- 离开会话；
- 播放失败；
- 开始/接听语音或视频通话；
- 用户手动播放其他媒体；
- 下一条已经听过、撤回、不可访问。

把 queue selection、starting/playing/completed/error 做成独立 controller，不要继续堆在页面 State 里。

## Part D：语音转文字（STT）

### 架构

DD 是 self-hosted 产品，禁止让客户端硬绑定某一家云服务。

实现 server-side `TranscriptionProvider`（或等价接口）：

- 默认未配置时明确返回 `VOICE_TRANSCRIPTION_UNAVAILABLE`。
- 至少支持可配置的 Whisper-compatible HTTP transcription endpoint，允许部署者指向自托管服务。
- provider URL/model/credential 只来自服务端配置。
- 客户端不能获得 provider credential。
- 普通日志不能记录完整音频内容或凭据。

### 持久化

开工确认 migration 号；如 `000035` 未占用，优先：

`000035_voice_transcriptions`

建议生命周期：

`PENDING -> RUNNING -> COMPLETED / FAILED`

至少关联：message、status、transcript、时间；可保存非敏感的 language/model/error category。

### 授权

- 只有仍有权读取该 VOICE message 的会话成员才能请求和读取 transcription。
- 非 VOICE message 必须拒绝。
- recalled/越权消息不能通过 transcript 泄漏原内容。
- 防 IDOR。

### API

设计正式 `/api/v1/...` API并同步 OpenAPI，支持：

- 请求单条转写。
- 查询 status/result。
- 重复请求幂等，不创建无限任务。
- provider 未配置、临时失败、永久失败有结构化错误码。

优先复用现有 worker/job 模式，避免 HTTP request 因大音频长时间阻塞。

### 全部自动转文字

这是用户级 preference：

- enabled/disabled 明确持久化。
- enabled 时只对新收到且尚无 transcript 的 VOICE 发起任务。
- App 重启不能把全部历史反复重新提交。
- provider 未配置时 UI 能识别“不可用”，不能开关假成功。
- 先检查项目现有 preference 架构并复用；不要造第三套临时设置。
