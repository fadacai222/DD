## 已确认的高可信根因

现有代码已经有：

- migration `000025_group_calls`
- `/api/v1/groups/{groupId}/calls`
- active/join/leave API
- GroupCall client/page
- LiveKit room token
- 生产 LiveKit Compose

真正问题在配置路径：

`infra/prod/compose.yml` 给 API：

- `LIVEKIT_URL`
- `LIVEKIT_API_KEY_FILE=/run/secrets/livekit_api_key`
- `LIVEKIT_API_SECRET_FILE=/run/secrets/livekit_api_secret`

`appconfig.Load()` 会通过正式 secret reader 解析 `*_FILE`。

但是：

`server/internal/groups/calls.go::loadGroupCallMediaConfig()`

又直接读取：

- `os.Getenv("LIVEKIT_URL")`
- `os.Getenv("LIVEKIT_API_KEY")`
- `os.Getenv("LIVEKIT_API_SECRET")`

生产容器没有明文 `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` 环境变量，因此群通话会返回 `ErrGroupCallUnavailable`，最终 HTTP 503 `GROUP_CALL_UNAVAILABLE`。

这与 1v1 calls 使用 `appconfig` 注入配置的路径不一致。

## 必须实现

1. **消除 groups package 对 raw LiveKit 环境变量的隐藏依赖。**
2. 扩展 `groups.Config`，显式注入群通话所需：
   - LiveKit URL
   - API key
   - API secret
   - 如 participant limit 需要配置，也要决定是否正式注入，禁止继续散落环境变量读取。
3. `server/cmd/api/main.go` 必须把 `appconfig.Load()` 已经解析后的值传进 `groups.NewService(...)`。
4. `StartGroupCall` / `JoinGroupCall` 必须从 Service config 使用同一套配置。
5. secret 绝不能出现在 error/log/response。
6. dev/test 仍可使用普通 env 经 appconfig 解析；production secret file 必须真实可用。
7. 如果 LiveKit 配置真的缺失，仍应 fail closed 返回明确 unavailable，不能假成功。
8. 不得回退现有 group call 状态机、权限、人数上限、room/token 权限。
