# AI05 Telegram 贴纸包导入修复报告

状态：`FIXED-PENDING-RETEST`

## 根因

- 导入失败仅显示一次性 SnackBar，Dialog 关闭后贴纸面板没有持久错误状态。
- 客户端网络超时和连接失败没有稳定错误码。
- 服务端把 Telegram 上游的 400、401、429、5xx 统一压成 relay unavailable，无法给用户具体原因。
- 旧错误文案仍写成只支持静态 WebP，与当前 WebP/PNG、TGS、WebM 支持范围不一致。
- shared pack 卡片失败提示直接展示异常文本，没有复用贴纸库的错误文案。

## 修复结果

- 贴纸面板增加常驻反馈条，SnackBar 仅作辅助提示。
- 重试先清旧错误；成功切换到新 pack；部分成功展示成功数和失败数。
- 服务端区分 pack 不存在、relay 鉴权失败、Telegram 限流、上游 timeout、上游不可用。
- 客户端区分请求超时和连接失败，并保留 machine code / HTTP 状态用于诊断；总集成复审进一步给所有 Sticker HTTP 请求加了 15 秒硬超时，避免只捕获异常却没有真实 timeout deadline。
- 全包均超限时返回 TOO_LARGE，不再误报格式不支持。
- shared pack 导入失败使用同一错误文案。
