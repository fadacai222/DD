## 1. 根因与边界

现有聊天页语音点击路径会先 `await` 完整媒体 bytes，再切播放状态；同时旧路径可能在播放器真正开始前就写入 heard，因此网络慢时首播不跟手，失败也可能错误清除“未听”。本轮没有扩大修改 `text_chat_page.dart`，而是把可复用底层能力拆到独立 source / resolver / controller / selector，留给 Wave3 统一接线。

服务端此前没有语音转文字的持久化事实、provider 抽象、正式 API 或 worker，因此不能安全支持单条 STT 和自动 STT。本轮新增完整基础链，但不把任何 provider credential、endpoint 或音频内容下发客户端/写日志。

## 2. 语音播放能力

新增 `VoicePlaybackSource`：

- 本地缓存文件 `LocalVoicePlaybackSource`
- 短时授权 URL `RemoteVoicePlaybackSource`
- 有界 bytes fallback `BytesVoicePlaybackSource`

新增 `AuthorizedVoicePlaybackSourceResolver`：

- 缓存命中优先本地文件/bytes，不请求新 grant。
- 缓存未命中只等待授权 URL，立即返回给播放器，不再等待完整下载。
- 首播同时可做有界后台缓存；默认后台缓存/bytes fallback 上限均为 8 MiB，prefetch 默认最多 2 条。
- 远端播放失败时只刷新一次 grant；第二次远端播放仍失败后才允许有界 bytes fallback，不做无界重试循环。
- 下载继续复用既有授权下载合同，不绕过 Media ACL。

新增 `VoicePlaybackController`：

- 点击后同步进入 `starting`，网络下载 future 未完成时 UI 已可展示加载态。
- 只有播放器真实发出 `playing=true` 后才调用 `markHeard`。
- 所有 source 都失败时恢复 `idle`，并发稳定错误 `VOICE_PLAYBACK_FAILED`。
- 只在用户主动点击未听的远端 VOICE 后开启顺序连播。
- completion 只继续同会话后续合格未听 VOICE。
- 暂停/手动停止、离开会话、通话开始、其他媒体开始都会终止自动队列；下一条远端 VOICE 若已听/撤回/不可用则停止，不跨过去继续外放。

未听判定独立放在 `VoiceMessageSelector`：远端发送、VOICE、未撤回、有 media、当前 `isVoiceHeard(messageId)==false` 才算未听；自己发送的语音不会产生未听状态。

## 3. STT 持久化与 worker

新增 migration：

- `000035_voice_transcriptions.up.sql`
- `000035_voice_transcriptions.down.sql`

新增表：

- `voice_transcription_preferences`
  - 用户级 `auto_transcribe_enabled`
  - `enabled_at` 作为自动模式时间边界
- `voice_transcriptions`
  - `message_id UNIQUE`
  - `PENDING / RUNNING / COMPLETED / FAILED`
  - transcript / language / model
  - attempts / retryable / error_category
  - available / lease / started / completed 时间字段

worker 使用 `FOR UPDATE SKIP LOCKED` + lease 抢占任务，provider 临时失败进入有界重试，worker 崩溃后过期 RUNNING lease 可重新领取。

自动 STT 只扫描：

- 当前 active member；
- 非发送者；
- 用户已显式开启自动 STT；
- message 创建时间不早于偏好 `enabled_at`；
- message 创建时间不早于成员 `joined_at`；
- VOICE 未撤回、未全局删除、未对该用户本地删除；
- 该 message 尚无 transcription row。

因此不会因为 App 重启去扫开启偏好之前的历史消息，也不会把入群前的语音当成“新收到”。

## 4. Provider 与服务器配置

新增 `WhisperHTTPProvider`，采用 Whisper-compatible `multipart/form-data`：

- `VOICE_TRANSCRIPTION_ENDPOINT`
- `VOICE_TRANSCRIPTION_MODEL`
- `VOICE_TRANSCRIPTION_CREDENTIAL` / `VOICE_TRANSCRIPTION_CREDENTIAL_FILE`

endpoint/model 必须成对配置。provider 未配置时：

- 单条 STT 返回 `VOICE_TRANSCRIPTION_UNAVAILABLE`；
- preference API 报 `providerAvailable=false`；
- 不允许把自动 STT 假开启为 true；
- 普通聊天/语音播放不受影响。

生产 Compose 已把 credential 接为独立 `./secrets/voice_transcription_credential`，API/worker 都只从服务端读取。provider 请求错误只记录分类/HTTP 状态语义，不记录 credential、音频 bytes、转写正文或 provider response body。

## 5. 正式 API

新增：

- `POST /api/v1/messages/{messageId}/transcription`
  - 幂等请求单条转文字；PENDING/RUNNING 返回 202，已有 terminal 结果返回 200。
- `GET /api/v1/messages/{messageId}/transcription`
  - 查询状态/结果。
- `GET /api/v1/voice-transcription/preferences`
- `PATCH|PUT /api/v1/voice-transcription/preferences`

OpenAPI runtime route contract 同步更新。

客户端新增 `VoiceTranscriptionApiClient`，只认识正式 DD API，不持有 provider endpoint/model/credential。

## 6. 鉴权与隐私边界

每次手动 Request/Get 和 worker 真正处理前都重新验证：

- 当前用户仍是 active conversation member；
- message 仍存在且未全局删除；
- message 未撤回；
- message 没有被该用户本地删除；
- message 类型必须为 VOICE；
- PRIMARY media 必须 READY 且未删除。

无权用户统一得到 not-found 语义，不能利用 transcription API 探测其他会话 message 是否存在。即使 transcript 已存库，消息撤回/用户失去可见性后 `GET` 也不会返回正文；worker 在 provider 返回后、写 COMPLETED 前再次鉴权，处理期间发生撤回也不会把正文提交为可读取结果。
