## 最终契约

- 普通联系人 / 私聊 / 朋友圈等 viewer-relative 上下文：`viewer contacts.remark > users.display_name > handle(客户端兜底)`。
- 群上下文：`group_member_profiles.nickname > viewer contacts.remark > users.display_name > handle(客户端兜底)`。
- `contacts.remark` 始终是 owner-private。任何 remark join 都必须限定 `contacts.owner_user_id = 当前 principal/recipient`。
- `PublicContactUser.displayName` 继续表示公开昵称；Contacts 精确查询与 Mention 通过新增 `effectiveDisplayName` 返回 viewer-relative 名字。
- Messaging / Group / Moment 等本身由已认证 viewer 请求的 preview，现有 `displayName` 可直接承载 viewer-resolved 结果。

## Privacy threat cases

1. Alice 给 Bob 备注 `Boss`：Alice 的 direct conversation 返回 `Boss`。
2. Carol 没给 Bob 备注：Carol 仍得到 Bob 公共名。
3. Bob 查看 Alice：不会获得 Alice 给 Bob 设置的私人 remark。
4. remark 清空：下一次 API 立即 fallback 公共昵称。
5. remark 更新：下一次 API 立即返回新值，没有 stale 公共缓存。
6. 删除 Carol→Bob contact row：Carol 的 conversation preview 立即 fallback Bob 公共昵称。
7. Group member：Alice 的 Bob remark 不会泄漏给 Carol；Bob 群昵称存在时群昵称仍高于 Alice remark。
8. Moments：Bob 对 Alice 的私有备注只影响 Bob；Carol 仍看到 Alice 公共昵称。
9. Push：sender remark 只在 `job.RecipientUserID` 对应的 delivery query 中解析。
10. Calls：CALL_RINGING 的 callerName 只按 callee 解析；不把 private remark 放进共享 LiveKit participant token。
11. 未新增 Redis / 公共事实缓存，也未把 remark 写回 `users.display_name`、message、group 或 moment 持久化内容。

## 性能 / 索引

- 没有新增按 conversation 再发一次 API 请求查询 remark 的客户端 N+1。
- direct peer、group member、push、moment、call 都把 remark join 合并进既有 SQL。
- `contacts` 现有主键 `(owner_user_id, contact_user_id)` 可直接支持 viewer join，无需 migration。
- group avatar 只处理现有最多 4 个成员样本；没有新增 Redis cache。
