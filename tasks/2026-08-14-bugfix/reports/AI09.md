## pasteboard 实际 API / Windows 格式

项目现有依赖 `pasteboard: ^0.5.0` 已足够，不新增第二套 clipboard plugin。

实际 API：

- `Pasteboard.image`：读取剪贴板图片。
- `Pasteboard.files()`：读取剪贴板文件列表。
- `Pasteboard.text`：读取纯文本 representation。

`pasteboard 0.5.0` Windows 原生实现读取 `CF_DIB`，转换并写成系统临时目录中的 BMP，Dart 侧随后读取该 BMP bytes 并立即删除插件临时文件。因此 Windows 截图/bitmap 在 DD adapter 中通常表现为 `image/bmp` bytes。

Windows 文件复制走 `CF_HDROP`，`Pasteboard.files()` 返回文件 path；DD adapter 可直接识别 `.jpg/.jpeg/.png/.webp/.bmp`，不预先把整个文件读入内存。

## Adapter 契约

新增：`clients/app/lib/core/media/windows_clipboard_image_service.dart`

主要类型：

- `ClipboardGateway`：可注入 clipboard boundary，测试不依赖真实系统剪贴板。
- `PasteboardClipboardGateway`：正式 pasteboard 实现。
- `WindowsClipboardImageAdapter.readImage()`：每次调用都重新读取当前剪贴板，支持 bitmap bytes 与图片 file path。
- `ClipboardImagePayload`：统一返回 `bytes/path + mimeType + suggestedName + sizeBytes`。
- `ClipboardImagePayload.toXFile()`：可直接交给现有 `_sendImageFiles(...)`，不新造上传协议。
- `ClipboardImageError` / `ClipboardImageErrorCode`：坏数据、读取失败、超限、文件丢失均返回 typed error，不向 UI 泄漏未处理异常。
- `WindowsClipboardPasteDecider.decide(...)`：提供最终 Ctrl+V shortcut decision contract。

bytes 在 adapter 边界会验证：

- 非空；
- 不超过现有 `maxChatImageSourceBytes`（96 MiB）；
- 图片 header/decoder 可识别；
- 像素不超过现有 `maxChatImageSourcePixels`。

file path 在 adapter 边界会验证文件存在、非空、size 不超过 96 MiB，并对建议文件名做安全清洗。

## text / image precedence

决策语义：

1. 非 Windows 或 Web：`passThrough`，完全不读取 clipboard image，不改变现有粘贴行为。
2. Windows + image bytes/path：`consumeImage`。
3. image 与 text representation 同时存在：图片优先，不读取 text fallback。
4. 只有文字 / 空剪贴板：`passThrough`，让 TextField 继续原生粘贴。
5. 图片读取/解析失败且存在 text：`passThrough`，允许文本兜底。
6. 图片失败且无文本：`showImageError`，由聊天 UI 显示 `ClipboardImageError.message`。
7. 图片 Ctrl+V key repeat：`consumeDuplicateImage`，快捷键仍被消费但不产生第二个发送任务。

每次新的非-repeat Ctrl+V 都重新读取剪贴板，因此连续复制两张不同图片后粘贴会取最新内容。

## 复用现有图片发送链

Wave 3 不应新建上传逻辑。`decision.image!.toXFile()` 可以直接进入聊天现有 `_sendImageFiles(...)`，从而继续复用：

- 96 MiB source size validation；
- `processChatImage(...)` 图片解码、方向处理、metadata 清理、尺寸/质量压缩；
- `uploadChatImage(...)`；
- media confirm / `sendImage(...)`；
- `MediaTransferController` pending/progress/cancel/retry；
- 消息流本地 preview 与既有失败提示。

Adapter 自身不在桌面或当前工作目录创建临时图片。bitmap bytes 直接用 `XFile.fromData`；file clipboard 复用原始 path。`pasteboard` 自己为 Windows `CF_DIB` 创建的系统临时 BMP 会在插件 Dart 层读取后立即删除。

## Wave 3 chat composer 接线点

最终只需要在 Windows Ctrl+V 键处理处调用：

- `WindowsClipboardPasteDecider.decide(isKeyRepeat: event is KeyRepeatEvent)`。
- `passThrough` → 返回 ignored，让 TextField 原生处理文本 Ctrl+V。
- `consumeImage` → `_sendImageFiles(<XFile>[decision.image!.toXFile()])`，并返回 handled。
- `consumeDuplicateImage` → 直接 handled，不再次 enqueue。
- `showImageError` → `_showImageError(decision.error!.message)` 并 handled。

不要修改 Ctrl+C / Ctrl+X，也不要对普通按键或 IME composition 调用此 decider。

## 已知限制 / blocker

无代码 blocker。

有一个底层能力限制需要 Wave 3 / 后续性能验证注意：`pasteboard 0.5.0` 的 Windows `Pasteboard.image` 会先由原生插件把 `CF_DIB` materialize 成临时 BMP，再由 Dart 读取 bytes；因此对极端巨大的 bitmap，DD 只能在 bytes 返回后执行 96 MiB / pixel gate，无法在插件 materialize 之前做 size preflight。普通截图路径不受影响，但极端超大 DIB 的峰值内存仍受第三方插件实现约束。
