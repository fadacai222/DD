# AI03：iOS AppIcon 白边 + 聊天底栏色差修复报告

状态：`FIXED-PENDING-RETEST`

## AppIcon 白边根因最终证据

- iOS 构建入口 `clients/app/tool/generate_ios_app_icons.dart` 原先读取 `设计图/brand-assets/DD-icon-1024.png`。
- 共享品牌脚本 `scripts/generate-brand-assets.ps1` 原先生成该文件时明确使用 `Scale 0.86 + White background`，因此 iOS generator 实际拿到的是“已经缩小一圈并预铺白底”的派生图，再按 Contents.json 缩放到各 AppIcon 尺寸。
- 对仓库现有资源实测：旧 `DD-icon-1024.png` 的非白内容边界约只占宽 84.8%、高 85.7%；品牌母版 `设计图/logo.png` / `DD-logo-master.png` 的有效内容则已接近画布边缘（约宽 99%、高 100%）。这与主屏图标“整体缩一圈 + 白边”的现象一致。
- 修复后 iOS generator 直接读取未预缩放的 `DD-logo-master.png`；共享品牌脚本的 iOS 1024 canonical 改为 `Scale 1.00`。Android launcher、Windows ICO、Web icon 的既有缩放参数保持不变，并由 contract test 锁定。
- generator 新增 source guard：如果 source 外围存在明显整圈不透明近白 inset，则直接失败，防止未来再次把 0.86 白边派生图接回 iOS。
- 所有 `Contents.json` 声明尺寸均通过真实 manifest 生成测试；重复声明共用同一 filename 时按唯一输出文件校验。生成 PNG 均为 3-channel opaque RGB，包含 1024 marketing icon，无 alpha。

## 聊天底栏色差根因

聊天 body 已经使用 `ChatWallpaperSurface` 铺满整个 Stack，但 `_composerBar()` 原先又在 footer 外层使用：

```dart
Material(color: Theme.of(context).colorScheme.surface, ...)
```

因此 footer 整条区域始终是不透明 theme surface；纯白背景时不明显，自定义 wallpaper 下会形成明显横向色块，iOS SafeArea/home indicator 区域也无法与 wallpaper 连续。

修复后：

- footer 外层 Material 改为 transparent，让底层 `ChatWallpaperSurface` 连续显示到 composer 和 SafeArea。
- 输入框继续使用现有 filled input surface，不降低正文/placeholder 对比度。
- voice / emoji / `+` 按钮各自使用局部半透明圆形 surface，避免直接压在复杂 wallpaper 上看不清。
- 发送按钮仍沿用现有 FilledButton；未修改 voice、mention、clipboard、Live Photo 等逻辑。
