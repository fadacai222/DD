# AI01：群通话生产 LiveKit 配置修复报告

状态：`FIXED-PENDING-RETEST`

## 根因

生产 Compose 正确通过 `LIVEKIT_API_KEY_FILE` / `LIVEKIT_API_SECRET_FILE` 挂载 LiveKit 凭据，`appconfig.Load()` 也会解析 `*_FILE`。但群通话 `server/internal/groups/calls.go` 绕过 appconfig，直接读取 `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` 明文环境变量，导致生产容器群通话 Start/Join 返回 `ErrGroupCallUnavailable`，HTTP 映射为 503 `GROUP_CALL_UNAVAILABLE`。正式 1:1 Calls 使用的是已解析配置，因此不受这个缺陷影响。

## 改动文件

- `server/internal/groups/service.go`：扩展 `groups.Config`，显式接收 LiveKit URL、API key、API secret、群通话人数上限；Service 持有解析后的群通话运行配置。
- `server/internal/groups/calls.go`：Start/Join 改为只使用 Service config；删除 groups package 对 LiveKit/人数环境变量的直接读取；缺失配置继续 fail closed。
- `server/internal/platform/appconfig/config.go`：集中解析 `DD_GROUP_CALL_MAX_PARTICIPANTS`，默认 32，非法值回退安全默认；LiveKit secret 仍统一由正式 `ReadSecret()` 支持普通 env 与 `*_FILE`。
- `server/cmd/api/main.go`：将 `appconfig.Load()` 已解析的 LiveKit 配置和人数上限注入 `groups.NewService(...)`。
- `server/internal/groups/calls_test.go`：覆盖缺失配置 unavailable、人数边界和 LiveKit token 的目标 room/current identity 权限边界。
- `server/internal/groups/group_calls_integration_test.go`：PostgreSQL 生命周期测试改为显式 groups config，覆盖 Start/Join token 与人数限制。
- `server/internal/platform/appconfig/config_test.go`：覆盖群通话人数配置解析。
- `server/cmd/api/main_test.go`：覆盖 production 仅设置 LiveKit key/secret `*_FILE` 时 appconfig 解析并注入 groups.Config。
- `server/internal/httpapi/group_calls_test.go`：覆盖群通话 Start route 在可用媒体配置下返回 201，而非 `GROUP_CALL_UNAVAILABLE`。
- `docs/README.md`、`docs/15-当前实现状态与开发路线.md`：同步生产群通话状态为 `FIXED-PENDING-RETEST`。

## 生产真人复测步骤

1. 部署包含本修复的新 API image。
2. 确认 API 容器仅提供 `LIVEKIT_API_KEY_FILE` / `LIVEKIT_API_SECRET_FILE`（不提供明文 `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET`）时仍能正常启动。
3. 使用真实账号和真实群执行 Start group call，确认 HTTP 201。
4. 第二设备执行 Join，确认 HTTP 200。
5. 确认响应 `livekitUrl` 是生产 WSS 地址，token 非空。
6. 确认两台设备实际加入同一个 LiveKit room，并能看到/听到对方媒体。
7. 执行 leave，并确认最后一个 participant 离开后会话正常结束。
8. 另行验证公网 UDP / TURN / ICE；网络失败必须与本次 service config 缺陷分开判断，不能把 NAT/TURN 问题重新归类为 `GROUP_CALL_UNAVAILABLE`。

## 未验证风险

- 本机没有 PostgreSQL integration 环境，因此数据库真实 Start/Join/leave 生命周期依赖 CI 或生产/测试库复验。
- 尚未部署新 API image 到生产，真实 secret-file-only 容器启动、真实群 Start/Join 和同一 LiveKit room 媒体链仍需真人验证。
- 本修复不改变 TURN/ICE/NAT/UDP 网络配置；即使 503 配置错误消失，公网媒体仍可能因网络层失败，需要独立诊断。
- 未修改 1:1 Calls、CallKit、客户端通话状态机或 Production Compose，避免把已 HUMAN-PASS 的基础公网 1:1 主链带入本次回归范围。
