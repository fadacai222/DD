# AI12｜锁屏/前后台 Realtime 恢复修复报告

状态：`FIXED-PENDING-RETEST`

## 根因

本次问题不是单一的 reconnect timer 缺失，而是三个条件叠加：

1. `MainShellPage.didChangeAppLifecycleState()` 在 `resumed` 时没有触发 Messaging/Realtime 恢复，只刷新 Moments、Push、Calls 与 badge。
2. `MessagingCoordinator.recover()` 只在 `_realtime.state == disconnected` 时调用 `connect()`。锁屏、后台挂起、Wi-Fi/蜂窝切换后，底层 socket 可能已经 stale/half-open，但客户端枚举仍暂时保持 `connected`，因此恢复路径会直接跳过 realtime。
3. Realtime 已有 heartbeat 5s + timeout 5s 与 1/2/4/8/16/30s backoff，但移动平台后台/锁屏会暂停或延迟 Dart timer；因此不能依赖 heartbeat 一定在回前台前完成 stale socket 判死。

另一个必须规避的风险是：原 `RealtimeClient.connect()` 只防 `_isConnecting`，并不防“已经 connected 又调用 connect”；如果 Shell 在 resumed 直接无脑 `connect()`，反而可能建立第二条 WebSocket 并覆盖 `_channel/_subscription`。

## 修复方案

### RealtimeClient

新增 `reconnectNow()` 作为单一职责的 immediate revalidation/reconnect primitive：

- 调用后明确进入 `connecting`；
- 取消当前 backoff timer，但不新增任何第二套常驻 retry timer；
- 停止旧 heartbeat；
- 先把旧 `_subscription/_channel` 从客户端状态机摘除，再 best-effort 关闭 stale socket；
- stale socket 的关闭最多等待 1 秒，避免 half-open transport 阻塞前台恢复；
- 随后通过统一 `_startConnectIfNeeded()` 建立唯一新连接；
- `connect()` 与 reconnect backoff 也统一走 `_startConnectIfNeeded()`，避免重复 channel；
- 多个并发 `reconnectNow()` 共用 `_reconnectNowInFlight`；
- 旧 channel 的迟到 `onDone/onError` 继续由现有 identity guard 拦截，不会把新连接打回 disconnected；
- 新连接失败后仍复用原 `_scheduleReconnect()` 指数退避。

### MessagingCoordinator

新增明确的 `onAppResumed()`，Shell 不再拼装 Messaging 私有细节。

恢复链：

1. realtime immediate revalidation；
2. conversation refresh；
3. durable pending flush；
4. cursor sync。

并发保护：

- `initialize()` 使用 `_initializeInFlight`，重复初始化不重复订阅 realtime stream；
- `_eventSubscription/_stateSubscription` 只创建一次；
- recover/resume 使用 `_recoveryInFlight` 串行；
- 多个连续 resumed 在当前强制 reconnect 已进行时直接共用当前恢复，不再排第二次 reconnect；
- 如果普通 recover 正在执行时收到 resumed，则保留一次“恢复后强制 realtime revalidation”的 pending intent；
- controlled initialize/recovery 期间，connected state listener 不再额外并发触发一套 flush/sync。

Realtime 暂时失败不会阻断 REST、conversation refresh、pending queue 与 cursor sync。

### Shell

`AppLifecycleState.resumed` 现在额外调用：

`_messagingCoordinator.onAppResumed()`

现有以下行为全部保留：

- Moment activity refresh；
- `_pushRegistrationService.onAppResumed()`；
- `_recoverCallFromExternalSignal(clearWhenMissing: true)`；
- notification badge sync。

没有修改 `conversations_page.dart`，没有修改 Push/Auth lease、Calls server state machine/formal token，也没有修改 `two_party_call_controller.dart`。

## 真人验收步骤

1. App 在线，确认连接绿点。
2. 锁屏/后台 1 分钟后回 App。
3. 锁屏/后台 5 分钟后回 App。
4. 锁屏/后台 30 分钟后回 App。
5. 每次回 App 应短暂进入“连接中”，随后恢复绿色；不应要求杀后台重启。
6. 锁屏期间让另一设备连续发送多条消息；恢复后应由 cursor sync 全部补齐，不能漏消息。
7. 补齐后继续让另一设备发送消息，必须继续实时收到，不能出现“只补历史、WebSocket 仍离线”。
8. 同时回归 1:1 来电：锁屏/恢复后由对端呼叫，仍应通过 shared realtime/durable sync/authoritative active-call recovery 收到来电。
