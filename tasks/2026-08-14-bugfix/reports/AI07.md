## Schema / migration

新增 `000034_message_mentions`，字段为 `message_id`、`conversation_id`、`sequence`、`mentioned_user_id`、`mention_all`。主键 `(message_id, mentioned_user_id)`；viewer 查询索引 `(mentioned_user_id, conversation_id, sequence DESC, message_id)`。

migration 会从现有 server-authored entities 回填 GROUP direct mention 与 `MENTION_ALL`，排除 sender 自己；direct UUID 使用条件转换，重复 direct/@all 先去重，`entities` 不是 JSON array 时按空数组处理，避免历史异常 entity 让升级失败。真实 PostgreSQL 18.4 已验证 000034 up/down/up roundtrip，并额外实跑重复 @all/direct + 非数组脏 JSON 的 000033 -> 000034 回填测试。

## 写入与状态语义

TEXT send 使用现有服务端 mention resolver 的 authoritative entities，并在同一事务写 message + mention index。客户端伪造 `content.entities` 仍会被 normalization 清空。GROUP direct mention 只接受 ACTIVE member；`MENTION_ALL` durable recipients 再按 sender role 校验，仅 OWNER/ADMIN 展开且不包含 sender。

edit 会按最新 authoritative entities 重建该 message 的 index；recall 同事务删除 index。read 不新增第二套 boolean，summary 只取 `sequence > last_read_sequence`，所以 read cursor 到达 mention sequence 后提醒自然消失。账号匿名化会显式删除该 viewer 的 mention rows。

## Conversation / API

Go `Conversation`、OpenAPI 和 Flutter `ConversationItem` 新增：

- `latestUnreadMentionMessageId: string | null`
- `latestUnreadMentionSequence: int64 | null`

仅当前 principal 的 GROUP summary 有值；无目标、DIRECT、SELF 为 null。List/Get conversation 主查询通过 LATERAL lookup 使用 mention viewer 索引按 sequence DESC `LIMIT 1`，不扫描消息正文，也没有新增每群一次的 DB roundtrip。查询同时核对 message id/conversation/sequence、ACTIVE membership、read cursor、recalled/deleted 状态，并排除当前 viewer 已执行 local delete 的消息。
