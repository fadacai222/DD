> 如果某个容器内部 codec 当前平台确实无法解码，应显示明确“不支持该编码/无法播放”，不能上传完后只报含糊的发送失败。

## I02｜发送链

❌选择视频后先在本地读取宽高/时长/Poster，不会先把整个视频上传完再回服务器读元数据。

❌本地无法读取的视频会在上传前明确报错。

❌主视频与 Poster 分别使用正确 media reservation。

❌上传进度与真实传输进度一致。

❌点击“取消视频上传”后网络上传确实停止，不只是 UI 消失。

❌临时 5xx/断网恢复时会进行受控重试，不无限重传。

❌4xx/权限/协议错误不会无脑重试。

## I03｜大文件

- [ ] 测试至少一个 >500 MiB 视频，上传过程内存不会随文件大小线性暴涨。
- [ ] 如条件允许再测 1～2 GiB 视频。
- [ ] 上传过程中仍能滚动聊天列表/切页面，不长时间假死。

## I04｜播放与本地缓存

1. 接收端第一次点视频。
- [ ] 第一遍立即走流媒体播放，不会为了“先缓存完整文件”卡在加载页很久。
- [ ] 播放时后台缓存有轻量进度，不影响控制。
- [ ] 退出再打开同一完整缓存视频，明显不再重新完整下载。
- [ ] 离线后已完整缓存的视频仍能播放。
- [ ] 签名 URL 过期后可自动拿新 grant 重试。
- [ ] 播放失败页有“重试”，不是死页。
- [ ] 竖视频不拉伸。
- [ ] 横视频不拉伸。
- [ ] 普通视频播放不会把整个 App 永久锁成横屏。

## I05｜失败对象回收语义

此项主要由自动测试/worker 覆盖，人工只观察异常：

- [ ] 视频上传后若 Poster/消息发送失败，重新发送不会因为旧 reservation/object 冲突。
