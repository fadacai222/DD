# ADR-004：端到端加密不自研密码协议

## 状态

Accepted

## 日期

- 提议：2026-08-07
- 原则确认：2026-08-10
- 当前实现复核：2026-08-13（历史 PoC 保留；Production E2EE 已移出 V1）

## 背景

DD 不排除未来重新立项支持 E2EE，但 Production E2EE 已明确移出 V1。密码协议的安全性不来自“算法看起来复杂”，而来自成熟公开设计、实现审计、测试向量、互操作与长期维护。

自行拼装 X25519/AES/ChaCha、自己设计 ratchet 或设备密钥分发，会制造高概率的不可见安全漏洞。

## 决策

DD 不自行设计端到端加密协议或密码原语组合。

正式 E2EE 必须基于经过现实使用和公开审查的成熟协议/实现，并保持：

- 设备级 identity。
- 异步 pre-key 建链。
- forward secrecy。
- post-compromise security（协议具备时）。
- 多设备。
- 重放/乱序处理。
- 版本化 serialization。
- 固定 interoperability vectors。

## 重要边界

`vodozemac` 当前只是候选 PoC，**本 ADR 并没有决定“生产必须永远使用 vodozemac 0.10.0”**。

最终库冻结前必须重新检查：

- 最新维护状态。
- Security audit。
- License。
- Native FFI/Web WASM。
- Multi-device needs。
- Group encryption roadmap。

如果最终换库，不需要推翻本 ADR；本 ADR 约束的是“不自研协议”。

## 当前 E2EE 状态

正式消息当前仍是服务端可解析内容：

- TEXT content JSON。
- server-side Mention parse。
- server-side search。

`ENCRYPTED` message type 和 `media.encryption_mode=E2EE` 是预留，不代表已加密。

产品当前禁止宣称：

```text
端到端加密已启用
服务器无法读取消息
```

## 备选方案

### 自己基于 libsodium 拼协议

拒绝：libsodium 提供原语，不自动提供正确的完整多设备消息协议。

### 自己实现 Signal/Olm 论文

拒绝：实现细节、序列化、乱序、状态恢复、密钥删除都极易出错。

## 后果

正面：

- 降低密码设计风险。
- 可依赖现有测试/生态经验。

成本：

- 需要 Rust FFI/WASM 或其它成熟跨平台桥。
- 协议升级受上游兼容性影响。
- E2EE 会影响 Mention、Search、Notification、Backup、Report 等现有功能。

## 上线约束

在以下条件前不得显示安全承诺：

- Final library/protocol ADR。
- 多平台互操作测试。
- Multi-device。
- Attachment encryption。
- Device verification。
- Persistence/restart。
- Backup/migration decision。
- Security review。
