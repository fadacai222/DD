# ADR-006：参考微信式交互，但不复制第三方品牌资产

## 状态

Accepted

## 日期

- 提议：2026-08-07
- 确认落地：2026-08-10
- 当前产品基线复核：2026-08-11

## 背景

DD 的产品方向明确需要：

- 微信式低学习成本信息层级。
- Telegram 式开放性、性能与功能密度。

但如果直接复制微信/Telegram 的商标、图标、通知音、贴图、专有图片或完整品牌视觉，会产生法律、开源分发和品牌独立性风险。

## 决策

DD 参考 **交互模式与通用信息架构**，使用自己的品牌资产和设计 token。

允许参考：

- 四主入口导航心智。
- 联系人/聊天/我的层级。
- 消息气泡、输入栏、资料页等通用 IM 交互。
- Telegram 的转发/收藏/编辑/Sticker/缓存等产品能力。
- 桌面端高信息密度和快捷操作。

禁止直接复制：

- 微信/Telegram Logo。
- 商标性图标。
- 原始通知音/来电音。
- 官方 Sticker/Emoji 素材包。
- 第三方 app 内专有插画/图片。
- 能造成用户误认产品来源的视觉资产。

## DD 当前自有方向

- 品牌名：DD。
- 自有 Logo / App Icon。
- 自有 notification small icon `ic_stat_dd`。
- 自有 message/ringtone/call sounds。
- 自有 `DdColors`、`DdRadii`、Desktop/Mobile tokens。
- Android Bottom Footer 虽参考 Telegram 的悬浮 pill 产品感觉，但使用 DD 自己的尺寸、颜色、组件和图标语义。

## 微信参考边界

我们参考“用户已经形成的通用 IM 心智”，例如：

```text
联系人默认显示联系人
点击头像看大图
好友申请在新的朋友
聊天输入区底部
危险删除是红色
```

这类常见交互不是为了伪装成微信，而是降低学习成本。

## Telegram 参考边界

Telegram 更多是能力和性能参考：

```text
消息编辑
长期撤回
转发
Saved Messages
Sticker Pack
媒体本地缓存
多端同步
快速动画
```

不会把 Telegram 品牌视觉原样搬进 DD。

## WhatsApp

当前产品明确不以 WhatsApp 作为主要视觉目标。

这不是技术限制；只是 DD 的既定产品方向。

## 后果

正面：

- 用户容易上手。
- DD 可以保持独立品牌。
- 开源发布法律风险更低。

成本：

- 需要自己设计/生成 icon、声音、Sticker 默认素材。
- 不能简单截图照抄像素。
- 每个平台仍要做细节设计。

## 约束

- 新增任何第三方图片/声音/字体/Sticker 前检查授权。
- 不把用户从 Telegram 导入的 Sticker Pack 作为 DD 官方内置资产；它是用户主动导入的第三方内容，服务端需要遵守 provider/版权政策。
- 设计 review 同时比较微信的层级与 Telegram 的流畅度，但最终产出必须是 DD 组件/token。
