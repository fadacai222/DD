# ADR-004：端到端加密不自研协议

## 状态

Proposed

## 日期

2026-08-07

## 背景

项目的隐私定位要求端到端加密，但自行组合密码算法极易出现重放、乱序、多设备、密钥轮换和身份验证漏洞。

## 决策

- 不自行发明端到端加密协议。
- 私聊优先评估 X3DH/PQXDH、Double Ratchet 和 Sesame 类成熟模型与可用实现。
- 每个设备拥有独立身份密钥。
- 附件在客户端加密后上传。
- 群聊 E2EE 单独立项，评估成熟 Sender Keys 或 MLS 实现。
- 正式选定库前完成平台支持、维护状态、测试向量和许可证审查。

参考规范：

- https://signal.org/docs/specifications/x3dh/
- https://signal.org/docs/specifications/doubleratchet/
- https://signal.org/docs/specifications/sesame/
- https://datatracker.ietf.org/doc/rfc9420/

## 备选方案

### 只做 TLS 和数据库加密

拒绝作为最终隐私方案：部署者或数据库泄露仍可读取消息正文。

### 自建 AES + RSA/ECDH 方案

拒绝：缺少成熟会话管理、前向保密、失陷恢复、多设备和乱序处理。

## 后果

- E2EE 会显著增加消息模型、多设备同步、搜索、备份和迁移复杂度。
- 服务端全文搜索在 E2EE 会话中不可用，需客户端本地搜索。
- 密钥丢失可能导致历史消息无法恢复，产品必须明确提示。
- 宣称 E2EE 前必须通过测试向量、跨平台互操作和独立安全评审。
