# ADR-005：首版单实例，跨实例联邦后续再做

## 状态

Proposed

## 日期

2026-08-07

## 背景

“任何人都可自建”容易被误解为“所有自建实例必须互联”。联邦会引入跨域身份、服务器信任、签名、投递重试、远端封禁、垃圾流量、版本兼容和内容删除语义。

## 决策

- 1.0 前每个实例独立运行。
- 用户账号、好友和群均属于单一实例。
- 客户端可添加多个实例账号，但账号之间不自动互通。
- 联邦作为 2.x 独立项目，先制定协议和威胁模型。

## 理由

- 自托管目标在单实例模式下已经成立。
- 可先验证核心 IM 的可靠性和安全性。
- 避免在身份与消息基础尚未稳定时冻结跨服协议。

## 联邦前置条件

- 稳定的实例身份和密钥轮换。
- 服务器发现、签名和版本协商。
- 跨服消息幂等与退信。
- 跨服好友和群成员模型。
- 封禁、举报、滥用和服务器级阻断。
- E2EE 跨域设备密钥验证。
- 远端数据删除与保留语义。

## 后果

- 不同部署者的用户首版不能互加好友。
- 文档必须明确“可自建”不等于“已联邦”。
- 数据模型保留 `instance_id/domain` 扩展位，但不提前实现复杂联邦逻辑。
