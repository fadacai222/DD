# 测试、验收与发布标准

## 1. 测试目标

IM 的失败通常不是“页面打不开”，而是：

- 偶发重复消息。
- 断线后漏消息。
- 多设备未读数不一致。
- 好友删除、拉黑后仍可越权访问。
- 扫码登录被重放。
- 媒体对象被猜到地址后直接下载。
- 音视频在局域网可用、换运营商就失败。

因此测试必须覆盖状态机、重试、并发、权限、弱网和恢复，而不只是 UI 截图。

## 2. 测试分层

| 层级 | 目标 | 建议工具 |
|---|---|---|
| 单元测试 | 领域规则、状态机、校验、加密封装 | Go test、Flutter test、Vitest |
| 集成测试 | PostgreSQL、Redis、MinIO、SMTP、LiveKit 交互 | Testcontainers/Compose |
| 契约测试 | OpenAPI、WebSocket 事件、客户端 DTO | OpenAPI validator、schema tests |
| 端到端测试 | 注册到聊天、扫码登录、朋友圈、通话 | Flutter integration_test、Playwright |
| 安全测试 | 越权、注入、上传、限流、Token | OWASP ZAP、自定义测试 |
| 性能测试 | 消息吞吐、连接、同步、数据库 | k6、Vegeta、自定义 WS 压测 |
| 网络测试 | 弱网、断网、丢包、NAT、TURN | tc/netem、真实移动网络 |
| 灾难恢复 | 备份、恢复、升级、回滚 | 自动化演练脚本 |

## 3. 覆盖率原则

不追求虚假的全仓 100%。硬性要求：

- Auth、授权、好友状态机、消息幂等、会话序号、扫码登录状态机：分支覆盖率不低于 90%。
- 其余核心服务：行覆盖率不低于 80%。
- UI 像素和生成代码不纳入同等覆盖要求。
- 每个生产事故修复必须新增回归测试。

## 4. 核心测试矩阵

## 4.1 注册与登录

- 正常邮箱注册。
- 验证码过期、错误、重复使用、暴力尝试。
- 同邮箱并发注册。
- 同 handle 大小写和 Unicode 归一化冲突。
- 密码错误不泄露账号是否存在。
- Refresh Token 轮换。
- 旧 Refresh Token 重放后撤销 Token Family。
- 修改密码后会话策略。
- 设备远程退出。
- TOTP 时间漂移。

## 4.2 好友

- 发起、接受、拒绝、撤销申请。
- 双方同时发申请。
- 重复接受。
- 删除、重新添加。
- 拉黑后好友申请、消息、朋友圈、通话全部受限。
- 搜索限流和账号枚举。

## 4.3 消息可靠性

- 同一 `clientMessageId` 重试 1、10、100 次只产生一条消息。
- 两个设备并发发送，sequence 唯一且连续或具有明确空洞策略。
- 数据库写入成功、WebSocket 推送失败后，重连可同步。
- Outbox 重复消费不产生重复副作用。
- WebSocket 事件乱序、重复、丢失。
- 客户端断网发送后恢复。
- 服务端重启期间发送和同步。
- 时钟偏差 24 小时不影响权威排序。
- 撤回事件多设备一致。
- 消息回复目标已删除或不可见。

## 4.4 群聊

- 创建、邀请、退出、踢人、解散。
- 群主退出前转让。
- 普通成员调用管理员接口。
- 被踢后不能继续发消息、读新消息、使用旧 LiveKit Token。
- 群二维码过期、撤销、次数耗尽。
- 大群已读序号性能。

## 4.5 媒体

- 正常上传和确认。
- 上传大小与声明不符。
- MIME、扩展名、魔数不一致。
- 超大像素图片、压缩炸弹、恶意 SVG、可执行文件伪装。
- 预签名 URL 过期和跨用户使用。
- 未确认上传自动清理。
- 配额并发竞争。
- E2EE 附件对象只包含密文。

## 4.6 朋友圈

- 各种可见范围组合。
- 修改好友关系后可见性。
- 拉黑后可见性立即变化。
- 不可见用户尝试直接读取 momentId。
- 评论回复目标删除。
- 删除帖子后媒体引用和清理。
- 时间线分页无重复、无漏项。

## 4.7 扫码登录

- 正常创建、扫描、确认、消费。
- 未扫描直接确认。
- 已过期扫描。
- 已确认重复消费。
- 攻击者复制二维码在另一设备使用。
- 用户看到的设备信息与实际请求设备一致。
- 手机取消后 PC 无法登录。

## 4.8 音视频

至少在以下环境实测：

- 同一局域网。
- 不同家庭宽带。
- Wi-Fi ↔ 4G/5G。
- 双方都在对称 NAT 或严格防火墙环境。
- UDP 禁止，仅 TURN/TCP/TLS。
- 丢包、抖动、带宽下降。
- 来电时多个设备在线。
- 接听后其他设备自动停止响铃。
- 通话中切换前后台、蓝牙耳机、听筒和扬声器。

## 4.9 E2EE

- 官方测试向量。
- Flutter 各平台密文互通。
- 消息乱序、重复和跳号。
- 一次性预密钥耗尽。
- 新设备加入和旧设备撤销。
- 身份密钥变化提示。
- 附件加密、缩略图加密。
- 备份恢复后密钥缺失时明确失败，不伪装成消息损坏。
- 服务端数据库和对象存储中不存在明文样本。

## 5. API 验收

- OpenAPI 文档通过 lint。
- 客户端生成代码无未提交差异。
- 所有错误符合统一结构。
- 所有列表接口有上限和分页。
- 所有写接口有幂等或冲突策略。
- 所有资源接口有授权测试。
- 无内部数据库 ID、栈、SQL、Secret 泄露。

## 6. UI 验收

### 移动端

- 360dp 小屏不溢出。
- 横屏关键页面可用。
- 键盘弹出不遮挡输入框；聊天长历史场景下键盘升降不得持续触发明显掉帧，必须用 Profile/真机验证。
- 点击聊天空白区域可以自然收起软键盘。
- 长按消息/会话菜单紧凑、适合触屏；危险删除为红色；未读会话提供“标为已读”。
- 深色模式无不可读文字。
- 权限拒绝后有可恢复路径。
- 语音录制和通话状态清晰。

### 桌面端

- 最小窗口尺寸下可用。
- Windows 自绘窗口必须验证标题栏无异常色块、Win11 圆角正常、四边和四角 8 方向均可缩放；最大化不得覆盖任务栏。
- 会话列表、消息区、详情栏多栏布局，不能只是移动端页面横向拉宽。
- PC/Web 默认 `Enter=发送`、`Shift+Enter=换行`。
- 支持键盘导航和必要快捷键。
- 支持拖拽文件/图片上传、剪贴板粘贴图片。
- 系统托盘和通知策略。
- 聊天消息区域能看见发送中 / 已发送 / 已送达 / 已读 / 失败状态。

### Web

- Chrome、Edge、Firefox、Safari 支持范围内验证。
- 刷新后会话恢复。
- 置顶必须真实改变会话排序，刷新后仍保存。
- 免打扰必须保存并跨端同步；通知系统接入后必须真实影响通知行为。
- Emoji / Sticker / GIF / 图片入口在支持阶段可用且无布局溢出。
- Service Worker 更新不破坏当前会话。
- 摄像头/麦克风权限被拒后的提示。

### 聊天体验基线

- UI 布局和交互心智以微信式桌面/移动 IM 为参考，不接受明显 WhatsApp 化视觉漂移。
- 已读推进必须基于“当前聊天真实可见 + App resumed + 当前 route”，后台 Tab / `IndexedStack` 中仍存活的聊天页不得自动清未读；发送方不得因此收到假“已读”。
- 新消息必须保留会话未读数和红色角标，直到用户真实阅读或主动“标为已读”。
- 功能开放性以 Telegram 为参考，不因 UI 简化而人为砍掉 Emoji、GIF、贴纸、媒体、回复等核心表达能力。
- 自己消息撤回默认无时间上限；测试不得再把“超过 2 分钟禁止撤回”视为正确行为。
- 消息已读状态必须在聊天界面可见，只有数据库序号不算 UI 完成。
- 输入区不能长期只有文本框 + 发送按钮。
- 前台非当前会话应有软件内提醒；Windows/Android 在客户端进程仍存活的后台场景应有本地系统通知。**杀进程后可靠通知必须单独验证 Push Worker/FCM/APNs，不能拿本地通知冒充 Push 完成。**
- 聊天内语音/视频测试必须确认 LiveKit 服务实际运行并成功进入媒体房间；只有呼叫状态变成 accepted 不算通话成功。重复 hangup/accept/reject 不应因幂等重试把 UI 卡在 `INVALID_CALL_STATE`。

### 无障碍

- 键盘完整操作。
- 焦点可见。
- 屏幕阅读器标签。
- 文本放大 200%。
- 对比度符合 WCAG 2.2 AA。

## 7. 性能目标与测试

## 7.1 首版基线

目标场景：

- 1000 注册用户。
- 200 同时在线 WebSocket。
- 100 条消息/秒短时峰值。
- 单会话历史 10 万条消息仍可游标分页。

目标指标：

- 在线文本消息服务端处理 P95 < 300ms。
- 普通 API P95 < 500ms，不含大文件上传和异步处理。
- 同步 500 条事件 P95 < 2s。
- API 错误率 < 0.1%，排除合法 4xx。
- 消息重复率和确认丢失率为 0。

以上必须通过压测报告证明；硬件、数据量和配置需写入报告。

## 7.2 压测场景

- WebSocket 建连风暴。
- 心跳和在线状态。
- 热门群消息扇出。
- 大量离线设备推送。
- 图片预签名上传。
- Outbox 积压恢复。
- PostgreSQL 连接池耗尽。
- Redis 短暂不可用。

## 8. 故障注入

必须模拟：

- PostgreSQL 重启。
- Redis 清空或重启。
- Worker 崩溃。
- API 实例重启。
- MinIO 暂时不可用。
- SMTP 超时。
- Push 服务失败。
- LiveKit 不可用。
- 磁盘满。
- 系统时间偏差。

验收原则：

- 永久数据不因 Redis 丢失。
- 消息成功响应后不能永久丢失。
- 外部服务失败不能拖垮整个 API。
- 重试必须有上限、退避和死信/人工处置路径。

## 9. CI 质量门

每个 Pull Request：

- 格式化检查。
- 静态分析。
- 单元测试。
- 集成测试。
- OpenAPI lint 和破坏性变更检查。
- 依赖漏洞扫描。
- Secret 扫描。
- License 扫描。
- Docker 构建。
- Flutter Android/Web/Windows 至少编译检查。

主分支或 Release：

- 全量端到端测试。
- 镜像扫描和 SBOM。
- 安装、升级、备份、恢复测试。
- 性能冒烟测试。

## 10. 发布等级

### Alpha

- 只供开发和内部测试。
- 数据模型可能破坏性变化。
- 不承诺安全和数据兼容。

### Beta

- 核心流程完整。
- 提供升级路径。
- 已知限制明确。
- 不建议承载极敏感通信。

### Release Candidate

- 功能冻结。
- 安全审计完成或进入整改收尾。
- 备份恢复、升级回滚、压力和弱网测试通过。

### 1.0 Stable

- API、数据迁移和配置具有兼容承诺。
- 安全基线通过。
- 安装和运维文档完整。
- 有明确支持版本和漏洞响应政策。

## 11. 1.0 发布阻断条件

出现以下任一情况不得发布：

- 存在未修复的认证绕过、越权、远程代码执行或密钥泄露。
- 消息在常规断线重连测试中丢失或重复。
- 备份无法恢复。
- 数据库迁移无失败处置方案。
- 音视频只在开发者局域网测试过。
- iOS/Android 推送模型没有说明实际限制。
- 声称 E2EE 但未通过测试向量和跨平台测试。
- Docker Compose 依赖作者私有服务。
- 未完成第三方许可证审查。
