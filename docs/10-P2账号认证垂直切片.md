# 4. DDID 规则

数据库规范化值：

```regex
^[a-z][a-z0-9_]{2,31}$
```

即：

- 3～32 字符。
- 首字符小写字母。
- 后续小写字母/数字/下划线。

用户输入需要 normalize。

DDID：

- 唯一。
- 用于精确查找。
- 用于 Mention。
- 不是数据库主键。

所有消息/关系长期引用 stable `userId`，不能只存 DDID 文本。

# 5. 注册流程

## 5.1 API

```text
POST /api/v1/auth/register/email/send-code
POST /api/v1/auth/register
```

## 5.2 流程

```text
email
→ normalize
→ rate limit
→ generate code
→ hash with pepper
→ email_codes
→ SMTP

user submits code
→ verify unused/not expired/attempts
→ validate DDID/password/displayName
→ transaction create user
→ auth_password
→ privacy settings
→ device
→ session/token
```

## 5.3 原子性

注册不能出现：

- users 成功但 password 没有。
- device 成功但 token 没有。
- code 消费了但用户事务回滚后无法重试，除非合同明确。

当前 service 测试应作为这类回归基础。

# 6. 登录

API：

```text
POST /api/v1/auth/login
```

输入概念：

```text
email
password
device metadata
```

服务端：

1. Normalize email。
2. Login rate limit。
3. Verify Argon2id。
4. 检查 user status。
5. 创建/恢复 device session。
6. 发 Access + Refresh。
7. 记录 audit。

失败信息禁止泄露账号枚举细节。

# 9. Token 模型

## 9.1 Access Token

短期 bearer credential。

至少包含/绑定：

```text
userId
deviceId
expiry
```

每次业务请求服务端解析为 Principal。

## 9.2 Refresh Token

服务端只保存 token hash。

表中存在：

```text
family_id
parent_token_id
issued_at
expires_at
revoked_at
```

支持：

```text
refresh token A
→ use A once
→ revoke/rotate A
→ issue B same family
```

A 再次出现视为 replay，可撤销 family。

---

# 10. Refresh API

```text
POST /api/v1/auth/token/refresh
```

客户端规则：

- Access 到期/401 时可以尝试 Refresh。
- 同一客户端多个并发 401 应避免同时 refresh 导致 self-replay。
- Refresh 成功后统一更新 API/Realtime access token。
- 明确 Refresh unauthorized 才清会话。
- timeout/DNS/临时断网不清 Refresh Token。

# 11. Auth Boot

客户端当前存在独立 `AuthBootPage`。

启动状态机：

```text
loading secure vault
→ no session: login
→ session exists: refresh
    ├─ success: main shell
    ├─ auth invalid: clear + login
    └─ network/transient: retry UI, keep session
```

目的：

- 不先闪登录页再进主界面。
- 不把断网误判成退出登录。

# 12. Secure Session Vault

Native 使用：

```text
flutter_secure_storage
```

DD 对 Windows secure-storage 并发读写做了额外封装，避免多个同时 read-modify-write 破坏同一加密 JSON 文件。

开发时禁止：

- 多个自建 storage 实例无序并发写同 key set。
- 把 Refresh Token 复制到普通 SharedPreferences/明文 JSON。

# 13. 历史登录

历史登录用于 UX：

- 头像。
- 昵称。
- 邮箱或可识别账号信息。
- 最近使用时间。

不能保存：

- 密码。
- 明文 Access/Refresh Token 复制。

历史登录不是认证事实；点选历史账号仍需使用当前安全会话或重新登录。

# 22. 安全日志

`auth_audit_events` 用于记录高风险认证事件。

应记录：

- login success/failure summary。
- password reset。
- email change。
- device revoke。
- logout-all。
- refresh replay。

禁止 payload：

- password。
- code。
- token。
