# 1. 架构目标

DD 当前采用“先做强模块化单体，再按指标拆分”的路线。

目标：

- 小团队可维护。
- 自托管部署简单。
- 核心事务尽量在 PostgreSQL 单事务内完成。
- 实时体验低延迟，但不把 WebSocket 当唯一事实来源。
- 媒体对象不经过 Go API 全量中转。
- RTC 不自研 SFU。
- 安全边界在服务端实现，不依赖客户端隐藏按钮。

# 6. 服务端技术栈

## 6.1 Go 模块化单体

当前部署单元：

- `server/cmd/api`
- `server/cmd/worker`
- `server/cmd/migrate`

核心业务暂不拆微服务。

## 6.2 PostgreSQL

PostgreSQL 是业务事实源，负责：

- 用户/设备/认证。
- 联系人关系。
- 会话/成员。
- 消息。
- Outbox。
- Sync Cursor。
- 媒体元数据。
- Sticker metadata/subscription。

当前 migration：`000001` ～ `000016`。

## 6.3 Redis

Redis 是可选 realtime bus，不是消息事实库。

用途：

- 多 API 节点之间传播“某用户有新事件”的 hint。

即使 Redis 暂时不可用，正确架构方向仍应保证：

- 已提交 PostgreSQL 的消息不丢；
- 客户端之后能通过 Sync 补回。

## 6.4 S3 / MinIO

正式媒体采用 S3 兼容对象存储。

对象存储只保存 bytes；PostgreSQL 保存：

- owner；
- purpose；
- MIME；
- size；
- sha256；
- status；
- storage key；
- business references。

Bucket 必须私有。

## 7.6 Calls

P7 已把 Calls 从实验内存态正式化为独立 domain：

```text
server/internal/calls
PostgreSQL calls
/api/v1/calls
/api/v1/calls/active
/api/v1/calls/{callId}/actions
/api/v1/calls/{callId}/token
```

正式边界：

- caller/callee 身份来自 Bearer Principal，不接受客户端自报 caller identity；
- 仅联系人允许呼叫，Block 拒绝；
- PostgreSQL 持久化通话状态与版本；
- callee 多设备可响铃，首个 accept 的设备获得后续媒体控制权；
- 错误设备不能获取 LiveKit token 或挂断；
- Call 绑定 DIRECT conversation；终态通话记录由服务端事务写入 SYSTEM message + Outbox。

旧 `/api/calls...` 只属于历史/兼容面，新客户端必须使用正式 `/api/v1/calls`。

# 8. 可靠消息架构

## 8.1 发送事务

```text
clientMessageId
→ authenticate
→ authorize conversation write
→ validate message payload
→ authorize media/reply/sticker
→ allocate sequence
→ insert message
→ update conversation last_message
→ insert outbox event
→ COMMIT
```

发送和 Outbox 必须同事务。

## 8.2 Outbox

Worker：

```text
claim outbox row
→ resolve recipients
→ write sync_events
→ publish realtime hint (if possible)
→ mark outbox published
```

如果 realtime publish 失败：

- 不应该回滚已经成功提交的业务消息；
- Outbox 使用 retry/defer；
- 客户端之后仍能通过 Sync 恢复。

## 8.3 Cursor Sync

每个用户消费独立递增 cursor。

```text
GET /api/v1/sync?cursor=N
```

客户端持久化最近 cursor。

WebSocket 断线、后台恢复、服务重启后都需要触发 Sync。

# 9. 会话模型

当前数据库 conversation type：

```text
DIRECT
GROUP
SELF
```

`GROUP` 已由 P6 正式实现，不再只是 schema 预留。`groups`、`conversation_members`、`group_member_profiles`、join request 与 Group Outbox 共同形成群生命周期，并复用 Messaging/Sync。

### DIRECT

- `direct_pair_key` 唯一。
- 关系删除后会话可以继续存在。
- Block 后写入被禁止。

### SELF

- 单用户成员。
- 用于 Saved Messages。

### GROUP

- `IMPLEMENTED + AUTO-VERIFIED / HUMAN-PENDING`。
- Owner/Admin/Member、邀请、审批、踢人、退出、群主转让、解散、群昵称/公告由服务端权限控制。
- GROUP 消息继续使用统一 conversation sequence、Outbox、Cursor Sync，不另造第二套消息系统。

# 12. 媒体架构

## 12.1 上传

```text
Client
→ POST media/uploads
← mediaId/uploadId/presigned PUT
→ PUT S3
→ POST complete
← READY
→ POST message referencing mediaId
```

客户端 Retry：

- PUT transport 失败后使用新 reservation。
- 失败、主动取消或准备重试前，客户端调用 `DELETE /api/v1/media/uploads/{uploadId}/cancel` 立即释放未完成 reservation；服务端 TTL 清理仅作为断网兜底，避免重复失败把 32 个 active slot / 512 MiB reserved quota 占满。
- complete 可针对同 uploadId 做有限幂等 retry。

## 12.2 下载

```text
Client has mediaId
→ POST /media/{id}/download-url
→ server authorizes user
← short-lived URL
→ direct GET object storage
```

## 12.3 本地缓存

客户端：

- download grant cache。
- media local cache。
- video file cache。
- `.part` 临时文件。
- expected-size 校验。
- aging/LRU 清理。

# 14. 通知架构

当前：

### App foreground

Realtime message → `MainShellPage`：

- active current conversation：不弹。
- muted：不弹。
- otherwise：DD overlay banner + message sound。

### Background but process alive

Realtime notice → `flutter_local_notifications`。

### Fully killed/offline

P10 已形成正式离线 Push 主链：notification preference、device push endpoint、durable push job、producer/service/API/Worker、FCM/APNs/UnifiedPush provider 与 Flutter token lifecycle 均已实现。Android 使用 data-only FCM 进入 DD 自定义通知链；iOS U30 已接 APNs/FCM permission/token/foreground/tap/badge 生命周期。真实 provider API success 仍不能替代 Android/iPhone 设备级 delivery/click 验收。

目标链：

```text
业务事件
→ Push Job producer
→ push_jobs
→ Push Worker
→ FCM/APNs/UnifiedPush
→ 客户端被唤醒/提醒
→ Cursor Sync 获取业务真相
```

Push 不持有第二份“消息真相”，未来 E2EE 也保持这个边界。

# 15. Windows Native 架构

Flutter Windows 使用自定义 runner。

当前 native 责任包括：

- 单实例。
- 自定义无边框窗口。
- Windows 11 DWM 圆角。
- `WM_NCHITTEST` resize。
- Flutter child HWND subclass，将边缘 hit-test 透传给 parent。
- DPI-aware min size。
- `WM_ERASEBKGND` 控制 resize 灰闪。
- 原生系统托盘：`Shell_NotifyIconW` 常驻图标、Explorer 重启后重注册、托盘菜单与恢复主窗口。
- Windows 关闭生命周期：标题栏 × / Alt+F4 / taskbar close 只隐藏到托盘；普通最小化仍保留任务栏；仅托盘“退出 DD”进入正常退出流程。
- 自定义 DD Windows 通知 popup channel。

这是高风险平台代码；修改后必须 Release build + 真人 DPI/resize 验收。

# 20. 扩展原则

只有满足以下条件才拆微服务：

- 已有真实容量指标证明模块是独立瓶颈；
- 数据一致性边界已经稳定；
- 有明确独立伸缩收益；
- 部署复杂度可被自动化承担。

在此之前继续保持：

```text
Go modular monolith
+ PostgreSQL transactional core
+ independent worker
+ optional Redis
+ external object storage / RTC
```
