# 5. 配置

## 5.1 基础

```text
IM_ENV=development|test|production
IM_PORT=18473
IM_PUBLIC_BASE_URL=...
IM_INSTANCE_NAME=DD
IM_ALLOWED_ORIGINS=...
IM_ALLOWED_HTTP_ORIGINS=...
```

## 5.2 PostgreSQL / Redis

```text
DATABASE_URL / DATABASE_URL_FILE
REDIS_URL / REDIS_URL_FILE
```

PostgreSQL 是必需生产依赖。

Redis 当前是可选 realtime hint bus；生产多 API 节点时应部署。

## 5.3 Auth / SMTP

```text
AUTH_TOKEN_SECRET / AUTH_TOKEN_SECRET_FILE
IM_REGISTRATION_MODE=open|invite|approval|closed
EMAIL_CODE_PEPPER / EMAIL_CODE_PEPPER_FILE
SMTP_HOST
SMTP_PORT
SMTP_FROM
SMTP_USERNAME
SMTP_PASSWORD / SMTP_PASSWORD_FILE
SMTP_REQUIRE_TLS
```

开发默认注册模式为 open；生产默认 closed，除非显式配置。

## 5.4 Media

```text
MEDIA_S3_ENDPOINT
MEDIA_S3_BUCKET
MEDIA_S3_REGION
MEDIA_S3_ACCESS_KEY / MEDIA_S3_ACCESS_KEY_FILE
MEDIA_S3_SECRET_KEY / MEDIA_S3_SECRET_KEY_FILE
```

只配置 endpoint 而不配置 bucket/credential 会启动失败。

## 5.5 LiveKit

```text
LIVEKIT_URL
LIVEKIT_PUBLIC_PORT
LIVEKIT_API_KEY / LIVEKIT_API_KEY_FILE
LIVEKIT_API_SECRET / LIVEKIT_API_SECRET_FILE
```

生产要求显式 `wss://` URL。

## 5.6 Telegram Sticker

```text
TELEGRAM_BOT_TOKEN / TELEGRAM_BOT_TOKEN_FILE
```

未配置时：

- Custom Sticker 应继续工作。
- Telegram Pack import 应返回明确未配置错误。

# 6. Production Fail-Fast

`IM_ENV=production` 下当前配置层已要求：

- `IM_PUBLIC_BASE_URL` 是 origin-only `https://`。
- 明确的 HTTP CORS origins。
- 明确的 WSS origins。
- 不允许全局 `*` wildcard。
- `LIVEKIT_URL` 为明确 `wss://`。
- LiveKit API credentials 完整。
- PostgreSQL URL 有效。
- Auth secret 长度达到要求。
- 注册开启时 Email Pepper、SMTP 完整。
- 注册开启时 SMTP TLS 必须启用。

生产配置校验失败应直接退出，不允许降级成不安全默认值继续运行。

# 7. Secret 管理

生产推荐：

```text
*_FILE
```

配合 Docker/Kubernetes secret 文件，而不是把 secret 写进 Git 或打包进客户端。

绝不提交：

- `infra/dev/.env` 的真实 secret。
- PostgreSQL password。
- Redis password。
- MinIO root credential。
- Auth signing secret。
- SMTP password。
- LiveKit secret。
- Telegram Bot Token。
- P10 FCM service-account / APNs signing key / UnifiedPush provider secret（实现后必须走环境变量或 `_FILE`，不得进客户端或 Git）。

`.env.example` 只能放占位值。

# 9. Worker

`server/cmd/worker` 当前承担两类已落地关键任务：

1. Messaging Outbox dispatch。
2. Media/Sticker cleanup。

P10 目标会增加第三类：**Push Job 消费与 provider 投递**。当前 `push_jobs` 已由 `000022_push.up.sql` / `000022_push.down.sql` 成对定义，但 Worker 还没有 Push consumer，因此生产部署不能声称已支持真正离线 Push。

生产运行时 API 与 Worker 必须都部署。

只运行 API 不运行 Worker 会导致：

- realtime/sync event 迟迟不出队；
- orphan media 累积；
- 部分异步清理失效。

必须为 Worker 增加独立 health/metrics/alerting，是生产化待办。

# 10. 对象存储

## 10.1 当前开发

MinIO bucket：

```text
dd-media
```

初始化脚本明确：

```text
anonymous set none
```

即私有 Bucket。

## 10.2 生产要求

- TLS endpoint。
- 私有 Bucket。
- 独立最小权限 access key。
- 生命周期策略不能与 DD Worker 清理逻辑互相破坏。
- Bucket CORS 只允许需要的客户端 origin/method/header。
- 当前 dev compose 的 `MINIO_API_CORS_ALLOW_ORIGIN=*` **只能视为开发便利配置，不得照搬生产**。

# 11. RTC / TURN

开发 Compose 当前启用 LiveKit + 内置 TURN UDP。

生产至少需要验证：

- WSS。
- UDP 可达。
- ICE/TCP fallback。
- TURN/UDP。
- 如目标网络需要，TURN/TLS 443。
- NAT 映射/public IP 正确。
- Android/Windows 不同网络互通。

“局域网能打电话”不等于 RTC 部署完成。

# 12. 邮件

开发：Mailpit。

生产：真实 SMTP。

要求：

- STARTTLS/TLS。
- 合理超时。
- 发送失败不能先持久化一个用户永远拿不到的验证码成功状态。
- 邮件供应商故障有明确错误和监控。
- 不在日志中记录验证码。

# 17. 备份

生产 1.0 必须覆盖：

### PostgreSQL

- 定期逻辑/物理备份。
- 加密存储。
- 恢复演练。

- versioning/复制策略按部署规模选。

### Config / Secret

- 配置模板纳入版本控制。
- Secret 单独安全备份。

### 恢复验收

必须真的执行：

```text
新机器
→ 恢复 DB
→ 恢复/挂载 object storage
→ 配置 secret
→ 启动 API/Worker
→ 客户端登录
→ 历史消息与媒体可用
```

只生成 backup 文件不算完成。

# 18. 升级

目标：

```text
backup
→ pull versioned images/binaries
→ migrate up
→ rolling/restart API + Worker
→ health check
→ smoke test
```

失败：

```text
停止继续升级
→ 判断 schema 是否可 down
→ 恢复应用版本
→ 必要时恢复 DB backup
```

不允许自动执行破坏性 downgrade 而不提示。

# 19. 生产 Compose 仍未完成

当前 `infra/dev/compose.yml` 是开发环境，不是生产模板。

正式 1.0 还需要：

- `infra/prod/compose.yml` 或等价模板。
- Reverse proxy/TLS。
- 独立 domain 配置。
- Secret file。
- 资源限制。
- 日志轮转。
- backup job。
- metrics/alerts。
- 对象存储生产 CORS。
- LiveKit/TURN 公网配置。
- 防火墙文档。
- 无开发 Mailpit。

因此文档不得写“任何人现在下载就能生产一键部署”。

# 20. 发布版本建议

当前阶段建议版本语义：

- `dev`：开发中。
- `alpha`：核心主链能用但明显缺模块/稳定性。
- `beta`：功能较全，集中真人与弱网测试。
- `rc`：功能冻结，安全/部署/恢复验收。
- `1.0.0`：所有发布门禁通过。

# 22. 运维禁止项

- 不允许生产数据库直接暴露公网。
- 不允许 Redis 无密码公网开放。
- 不允许 MinIO Console 对公网无额外保护。
- 不允许生产使用开发默认 secret。
- 不允许 Bucket public-read。
- 不允许把 Telegram Bot Token 打包到 APK/Windows/Web。
- 不允许为了排错打印 Access/Refresh Token。
- 不允许把 dev compose 的 CORS `*` 当生产模板。
