# 6. Production Fail-Fast

`IM_ENV=production` 下当前配置层已要求：

- `IM_PUBLIC_BASE_URL` 是 origin-only `https://`。
- 明确的 HTTP CORS origins。
- 明确的 WSS origins。
- 不允许全局 `*` wildcard。
- `LIVEKIT_URL` 为明确 `wss://`。
- LiveKit API credentials 完整。
- PostgreSQL URL 有效。
- Auth secret 长度达到要求。
- 注册开启时 Email Pepper、SMTP 完整。
- 注册开启时 SMTP TLS 必须启用。

生产配置校验失败应直接退出，不允许降级成不安全默认值继续运行。

# 9. Worker

`server/cmd/worker` 当前承担三类已落地关键任务：

1. Messaging Outbox dispatch。
2. Push Job 消费、FCM/APNs/UnifiedPush provider 投递、retry/backoff 与 invalid endpoint 生命周期。
3. Media/Sticker cleanup。

P10 Push consumer 已正式存在，不再是规划项。Worker 仍是生产必部署进程；只启动 API 会让 durable Outbox/Push backlog 持续累积。

生产运行时 API 与 Worker 必须都部署。

只运行 API 不运行 Worker 会导致：

- realtime/sync event 迟迟不出队；
- orphan media 累积；
- Push Job 不会实际投递；
- 部分异步清理失效。

U24 已为 Worker 增加独立 observability listener、`/live`/`/ready`/`/metrics`、dispatch heartbeat、Outbox/Push backlog 与正式告警。生产通过 `infra/observability/compose.yml` overlay 启用，9465 只应暴露在 Compose 内网。

## 14.1 U25 正式 Release Pipeline

正式 release 只由 `.github/workflows/release.yml` 的 `vMAJOR.MINOR.PATCH[-prerelease]` tag push 触发，不提供 `workflow_dispatch` 绕过入口。tag 必须精确指向当前 `origin/master` HEAD，且同一 commit 最多只能有一个 DD 正式 SemVer tag；其他非正式 tag 不影响。工作树必须 clean，`CHANGELOG.md` 必须有对应日期条目。完整 DAG、artifact 命名、签名 Secret contract 与验证方法见 `release/README.md`。

发布核心 gate：

```text
exact tag/SemVer/changelog/clean/master SHA
→ exact-SHA ci.yml success
→ exact-SHA secret-scan.yml success
→ Trivy dependency HIGH/CRITICAL = 0
→ Web/Android/Windows/Server build + Codemagic signed iOS build
→ native signing verification + SPDX SBOM + server image scan
→ SHA-256 + Sigstore keyless checksum signature + GitHub Artifact Attestation
→ production-release Environment approval
→ immutable GHCR SemVer image tags + image signing/attestation
→ GitHub Release
```

Android 正式构建要求 `release-signing` Environment 中的真实 JKS Secret 与预期 certificate SHA-256；Windows 要求真实 PFX、预期 certificate thumbprint 与 HTTPS RFC3161 timestamp URL。iOS 则由同一 `release-signing` gate 通过 `DD_CODEMAGIC_API_TOKEN` + `DD_CODEMAGIC_APP_ID` 触发 Codemagic `ios-signed-release`，Apple `.p8`、distribution certificate、provisioning profile、Bundle/Team identity 只存在 Codemagic Secret/Integration。Codemagic 在 App Store Connect publishing 前必须先捕获实际解析的 native dependency evidence，并用固定版本、固定 checksum-manifest SHA256 的 Syft/Trivy 生成非空 SBOM 与漏洞报告；Trivy `HIGH/CRITICAL --exit-code 1`、scanner 下载/完整性失败、空 evidence/report 均直接阻断 Apple upload。之后仍验证 `codesign`、embedded profile、Bundle/Team identity 与 SemVer/build-number，才允许输出 `DD-<tag>-ios-arm64.ipa`。GitHub 再对同一 evidence 做第二次 pinned Syft/Trivy 验证。缺 Secret、签名失败或 identity 不一致时直接失败，不会退化为 unsigned/ad-hoc 正式发布。普通 `ci.yml` 为兼容现有 smoke build 仍允许 Android release build 使用 debug signing，但 U25 formal release 显式设置 `DD_ANDROID_REQUIRE_PROD_SIGNING=true`，二者不可混淆。

`production-release` Environment 必须由项目所有者在 GitHub 设置 Required reviewers；reviewer 列表属于 GitHub 外部配置，仓库只能绑定 Environment，不能伪造“已审批”。iOS signed workflow 会自动上传 IPA 到 App Store Connect，Apple/TestFlight processing 可以发生；但明确 `submit_to_testflight: false`、`submit_to_app_store: false`，不会自动提交 TestFlight Beta App Review/分发 tester groups，也不会自动提交 Production App Store review。正式 Actions release bundle 保留 90 天；iOS IPA、native dependency evidence、Codemagic pre-publish SBOM/Trivy 和 GitHub 二次验证 SBOM/Trivy 与其他平台一起进入 checksum/provenance/attestation/GitHub Release，GitHub Release assets/GHCR SemVer image tags至少保留当前和上一正式版本，包含 prerelease predecessor。回滚继续使用 U23 forward-only compatibility policy：旧应用接受新 schema 才允许 application-only rollback，否则恢复 verified pre-upgrade backup；不执行数据库 down migration。

# 20. 发布版本建议

当前阶段建议版本语义：

- `dev`：开发中。
- `alpha`：核心主链能用但明显缺模块/稳定性。
- `beta`：功能较全，集中真人与弱网测试。
- `rc`：功能冻结，安全/部署/恢复验收。

# 22. 运维禁止项

- 不允许生产数据库直接暴露公网。
- 不允许 Redis 无密码公网开放。
- 不允许 MinIO Console 对公网无额外保护。
- 不允许生产使用开发默认 secret。
- 不允许 Bucket public-read。
- 不允许把 Telegram Bot Token 打包到 APK/Windows/Web。
- 不允许为了排错打印 Access/Refresh Token。
- 不允许把 dev compose 的 CORS `*` 当生产模板。
