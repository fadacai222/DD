# 安全、隐私与威胁模型

## 1. 安全目标

本项目处理账号、联系人、聊天记录、媒体、设备密钥和实时音视频，属于高敏感系统。安全目标不是“加个 HTTPS 就算完成”，而是：

- 防止账号被接管。
- 防止用户越权读取他人数据。
- 防止消息、文件和朋友圈被伪造或篡改。
- 防止部署者、日志系统和备份系统无意泄露敏感数据。
- 防止垃圾注册、撞库、骚扰、批量爬取和拒绝服务。
- 在启用端到端加密时，服务端不能获取消息正文和附件明文。
- 安全事件可追踪、可处置、可告警。

## 2. 信任边界

```text
互联网用户
  → 反向代理/TLS
  → Core API/WebSocket
  → PostgreSQL/Redis/Object Storage
  → Worker/SMTP/Push/LiveKit

客户端本地环境
  → 本地数据库
  → 系统安全存储
  → 摄像头/麦克风/通知权限

实例管理员
  → 管理后台
  → 高权限 API
  → 审计日志
```

所有跨边界输入都视为不可信，包括：

- HTTP 请求体、Header、Cookie、查询参数。
- WebSocket 帧。
- 二维码内容。
- 文件名、MIME、文件二进制。
- SMTP、Push、LiveKit 等第三方返回值。
- 用户可编辑昵称、朋友圈文本、链接和文件元数据。
- 客户端上报的时间、设备名、网络状态。

## 3. 关键资产

- 密码哈希。
- 邮箱验证码和找回凭据。
- Access/Refresh Token。
- 设备身份密钥和会话密钥。
- 联系人和社交图谱。
- 消息正文或密文。
- 媒体文件。
- 朋友圈内容和可见范围。
- APNs/FCM、SMTP、S3、LiveKit 密钥。
- 管理员账号和审计日志。
- 数据库和对象存储备份。

## 4. STRIDE 威胁摘要

| 类型 | 典型威胁 | 必要控制 |
|---|---|---|
| 冒充 | 撞库、Token 盗用、伪造设备 | Argon2id、MFA、Token 轮换、设备绑定、异常登录提醒 |
| 篡改 | 修改消息、朋友圈、上传文件 | TLS、数据库约束、消息签名/AEAD、哈希、审计 |
| 抵赖 | 管理员否认封禁或删帖 | 独立审计日志、请求 ID、管理员操作原因 |
| 信息泄露 | 越权读取、日志泄密、对象存储公开 | 服务端授权、最小日志、私有 Bucket、短期签名 URL |
| 拒绝服务 | 注册轰炸、验证码轰炸、文件炸弹、WebSocket 洪泛 | 多层限流、配额、大小限制、超时、连接上限 |
| 权限提升 | 普通用户调用管理员 API | RBAC、服务端校验、独立管理域名、强制 MFA |

## 5. 身份认证安全

## 5.1 密码

- 使用 Argon2id。
- 参数按部署硬件基准测试后确定，不把过低参数写死。
- 每个密码独立随机盐。
- 可选服务端 Pepper，保存在 Secret 中，不进数据库。
- 不记录密码强度分数和明文。
- 密码重置后撤销所有或可选全部旧会话。

## 5.2 邮箱验证码

- 数据库存验证码哈希，不存明文。
- 验证码短时有效。
- 限制单邮箱、单 IP、单设备、单实例发送频率。
- 限制验证尝试次数。
- 返回统一响应，避免枚举邮箱是否注册。
- SMTP 失败不应泄露内部配置和供应商信息。

## 5.3 Token

- Access Token 短时有效。
- Refresh Token 使用高熵随机值，数据库仅存哈希。
- 每次刷新轮换 Refresh Token。
- 检测旧 Token 再次使用时，撤销整个 Token Family 并告警。
- Web 使用 HttpOnly、Secure、SameSite Cookie。
- Flutter 原生客户端使用 Keychain/Keystore/系统安全存储。
- 禁止把长期令牌存 localStorage、日志、崩溃报告或 URL。

## 5.4 管理员

- 管理员必须启用 MFA。
- 管理后台支持单独域名或 IP 白名单。
- 管理 API 与用户 API 权限中间件分离。
- 高风险操作二次确认并要求输入原因。
- 最后一个超级管理员不能被误删或降权。

## 6. 授权模型

身份认证回答“你是谁”，授权回答“你能否访问这个对象”。每个资源操作都必须在服务端验证。

### 会话

- 读取消息前确认当前用户是会话成员。
- 发送消息前确认成员状态正常、未被禁言、未被拉黑规则阻止。
- 下载附件前重新验证消息和会话归属，不能只凭对象 Key。

### 朋友圈

- 查询必须应用受众规则。
- 点赞和评论前验证帖子仍存在且当前用户可见。
- 被拉黑后立即停止后续访问，不依赖缓存慢慢过期。

### 群聊

- 管理员操作校验角色。
- 群主转让、解散、移除管理员属于高风险操作。
- 旧群二维码撤销后必须立即失效。

### 管理后台

- 使用 RBAC：超级管理员、用户管理员、内容管理员、只读审计员。
- 禁止仅靠前端隐藏按钮控制权限。

## 7. 端到端加密设计原则

## 7.1 硬规则

- 不自行发明协议。
- 不自行拼接 AES、RSA、ECDH 形成“自创加密”。
- 使用公开规范、成熟库和测试向量。
- 密钥生成和加解密在客户端执行。
- 私钥不得上传服务端。
- 加密前后元数据泄露必须在文档中诚实说明。

参考规范：

- X3DH：https://signal.org/docs/specifications/x3dh/
- Double Ratchet：https://signal.org/docs/specifications/doubleratchet/
- Sesame：https://signal.org/docs/specifications/sesame/

## 7.2 私聊 E2EE

建议模型：

- 每个设备拥有独立身份密钥。
- 服务端保存公开身份密钥、签名预密钥和一次性预密钥。
- 每对设备建立独立会话。
- 发送给一个用户时，为其所有已验证设备分别加密消息密钥或密文信封。
- 新设备加入需要明确安全提示。
- 用户可扫描安全码验证设备。

## 7.3 群聊 E2EE

群聊不能简单地“所有人共用一个固定 AES 密钥”。必须处理：

- 新成员加入。
- 成员退出或被移除。
- 设备新增和撤销。
- 密钥轮换。
- 消息乱序。
- 离线成员。
- 大群性能。

因此群 E2EE 单独立项，优先评估成熟的 Sender Keys 或 MLS 实现。没有安全审计前，不把“加密开关”当成已完成。

## 7.4 附件加密

- 客户端生成随机文件密钥。
- 文件在上传前使用 AEAD 分块加密。
- 对象存储只保存密文。
- 文件密钥通过 E2EE 消息发送。
- 缩略图也必须按同等隐私级别处理，不能偷偷上传明文缩略图。

## 7.5 通话 E2EE

LiveKit 可提供媒体端到端加密能力，但需要：

- 客户端正确管理房间密钥。
- 参与者变化时轮换密钥。
- 明确区分传输加密和真正 E2EE。
- 在各平台做互操作测试。

## 7.6 元数据限制

即使启用 E2EE，服务端通常仍可能知道：

- 哪些账号存在。
- 哪些设备属于某用户。
- 谁和谁在某个时间通信。
- 消息大小、频率和会话成员。
- IP、User-Agent 和推送 token。

客户端隐私说明不得声称“服务器什么都不知道”。

## 8. 文件上传安全

- 文件名只作展示，不参与真实路径。
- 同时检查扩展名、MIME 和文件魔数。
- 单文件和解压后大小限制。
- 拒绝路径穿越、双扩展名和可执行内容伪装。
- 图片解码使用受维护库并设置像素上限，防止解压炸弹。
- 压缩包默认不在服务端自动解压。
- Worker 使用低权限、隔离容器扫描。
- 对象存储 Bucket 默认私有。
- 下载使用短期签名 URL 或鉴权代理。
- 用户上传 SVG、HTML 等主动内容默认禁止或严格净化。

## 9. Web 安全

- CSP、HSTS、X-Content-Type-Options、Referrer-Policy、Permissions-Policy。
- 管理后台禁止被 iframe 嵌套。
- 严格 CORS 白名单。
- Cookie 会话需防 CSRF。
- React/Flutter Web 禁止直接渲染不可信 HTML。
- 链接预览必须防 SSRF：拒绝私网、环回、链路本地、云元数据地址，限制重定向和响应大小。
- WebSocket 校验 Origin、Token、协议版本和消息大小。

## 10. 滥用和风控

自托管不等于不要风控。公开实例如果没有风控，通常会先变成垃圾邮件和骚扰工具。

必须支持：

- 注册模式切换。
- IP、邮箱域、设备维度限流。
- 一次性邮箱域名黑名单可选。
- 好友申请和陌生人消息限额。
- 新账号冷却期。
- 批量搜索和枚举防护。
- 举报、拉黑、封禁。
- 管理员备注和封禁原因。
- 可选 CAPTCHA，但不能成为唯一防护。

默认推荐：

- 个人实例：邀请制。
- 团队实例：管理员审批或域名白名单。
- 公共实例：邮箱验证 + CAPTCHA + 新号限流 + 举报处置。

## 11. 日志和审计

### 普通日志禁止包含

- 密码、验证码。
- Access/Refresh Token。
- E2EE 私钥和会话密钥。
- 消息正文。
- 完整邮箱正文。
- 对象存储签名 URL。
- APNs/FCM/SMTP 密钥。

### 可记录

- requestId。
- 脱敏 userId/deviceId。
- API 路径、状态码、耗时。
- 错误码。
- 消息类型和大小区间，不记录内容。
- 管理操作对象和原因。

### 审计日志

- 独立表或独立存储。
- 只追加，不允许普通管理员修改。
- 包含操作者、动作、对象、结果、时间、请求 ID、来源 IP。
- 高风险日志保留期可配置。

## 12. 密钥与 Secret 管理

- `.env.example` 只放占位符。
- 生产 Secret 不进 Git、不进镜像。
- Docker Compose 支持 Docker Secrets 或挂载文件。
- 备份加密密钥与备份文件分离保存。
- 提供 Secret 轮换说明。
- LiveKit、SMTP、S3、Push 密钥支持平滑轮换。

## 13. 备份安全

- 数据库和对象存储备份均加密。
- 备份上传远端前加密。
- 定期做恢复演练，不能只检查“备份文件存在”。
- 备份日志不输出加密密钥。
- 删除账号后需说明旧备份中的数据何时随保留周期淘汰。

## 14. 安全测试门槛

发布前至少完成：

- 身份认证和授权单元/集成测试。
- IDOR/BOLA 越权测试。
- 注册、验证码、登录和好友申请限流测试。
- 文件上传恶意样本测试。
- SSRF、XSS、CSRF、SQL 注入测试。
- WebSocket 鉴权、超大帧、重放和断线测试。
- E2EE 官方测试向量和跨平台互操作测试。
- 依赖漏洞扫描、镜像扫描、Secret 扫描。
- 独立安全评审。

## 15. 漏洞披露

开源发布前必须提供：

- `SECURITY.md`。
- 私密漏洞报告邮箱或平台。
- 支持版本范围。
- 响应和修复流程。
- CVE 处理策略。
- 禁止研究者在公共 Issue 直接披露仍可利用的漏洞。
