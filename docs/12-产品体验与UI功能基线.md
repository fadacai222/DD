# DD 产品体验与 UI 功能基线

> 更新时间：2026-08-11（朋友圈/二维码/正式通话 UI 状态同步）
>
> 核心口径：**微信式信息层级 + Telegram 式功能开放性、性能与流畅度 + DD 自有品牌资产。**

---

# 1. 体验北极星

用户不应该感觉自己在使用“Flutter 工程 Demo”。

目标：

- 页面打开快。
- 输入立即响应。
- 消息立即出现 pending 状态。
- 媒体看过后快速再次打开。
- 导航和键盘动画稳定。
- 不反复弹技术错误码。
- 所有入口与状态符合常见 IM 心智。

# 2. 参考边界

## 2.1 参考微信

- 四主入口信息架构。
- 聊天/联系人/我的层级。
- 联系人默认列表。
- 克制的消息气泡与列表密度。
- 资料页从身份到操作的层级。
- 危险操作红色。

## 2.2 参考 Telegram

- 多端同步。
- 消息编辑。
- 不限微信式 2 分钟撤回。
- 转发、收藏、置顶、搜索。
- Sticker/GIF/媒体开放性。
- 本地缓存与快速二次打开。
- Desktop 信息密度。
- 动画反馈迅速。

## 2.3 不参考

- 不以 WhatsApp 的视觉与菜单作为设计方向。
- 不复制微信/Telegram logo、通知音、表情资产、品牌 icon。
- 不复制第三方专有布局像素到侵权程度；使用 DD 自己 token 和资产重做。

# 5. Windows 主窗口

默认产品验证尺寸：

```text
881 × 657
```

最小尺寸当前 native 约：

```text
720 × 520 logical pixels
```

并按 DPI 换算。

要求：

- 无突兀系统白色标题栏。
- 四边/四角 resize。
- Windows 11 圆角。
- 最大化不覆盖任务栏。
- 标题栏拖动/双击。
- 普通最小化：最小化到任务栏，不隐藏到托盘。
- 关闭按钮 / Alt+F4 / taskbar close：默认隐藏到系统托盘，进程继续运行。
- 系统托盘运行期间常驻；左键可恢复主窗口；右键提供“最小化到托盘/打开 DD”和“退出 DD”。
- 只有托盘“退出 DD”走产品内正常退出流程；Windows 关机、任务管理器强杀、进程崩溃等系统级终止不在此保证范围。
- 100/125/150% DPI 正常。
- Resize 无灰块/白边/黑角。

当前 native runner 已做 child Flutter HWND subclass，让 resize border hit-test 回到 parent；并已加入原生系统托盘与关闭到托盘生命周期。托盘注册失败时关闭操作会退化为普通最小化，避免窗口隐藏后用户无法找回。

系统托盘代码已通过 Windows Release build 与 Flutter 窗口按钮 contract test，真人仍需验证托盘图标、Explorer 重启、Alt+F4、任务栏关闭入口和右键退出。

# 9. 资料页

对方资料视觉层级：

```text
大头像
昵称
DDID
签名
关系状态
主操作（发消息/语音/视频/添加/同意）
备注/标签

```

Windows 通讯录右侧联系人详情必须使用参考图同类的微信式资料布局：顶部为“头像 + 备注/昵称 + DDID + 右上更多”，中部按“朋友资料 / 朋友圈 / 更多信息”分组，底部使用无胶囊边框的图标动作“发消息 / 语音聊天 / 视频聊天”。禁止退回“头像居中 + 一排 Filled/Outlined 胶囊按钮”的旧版布局；备注/标签/个性签名/添加时间只显示真实现有数据，地区/来源等服务端没有的数据不做假占位。删除联系人、拉黑与朋友圈权限放右上更多菜单，危险操作仅危险项使用红色。

头像：

- 点击查看大图。
- 查看器支持保存。

自己的个人信息：

```text
我的
→ 个人信息
```

这里是昵称/DDID/邮箱/签名/头像主要编辑入口。

“我的”设置层级固定为：

- `账号管理`：展示已登录账号头像/昵称/DDID；点击已有账号直接切换有效会话，`添加账号` 进入登录页且不主动退出当前账号。
- `隐私与设备`：只承载隐私、登录设备与剩余系统管理项，不再重复外观/缓存/性能/传输设置。
- `外观`、`聊天背景`、`媒体与缓存`、`性能`、`传输中心`：全部直接放在“我的”外层，保证高频设置一层可达。
- 删除旧的 `刷新登录会话`、`切换账号` 两个独立入口；会话刷新属于内部机制，账号切换统一收敛到 `账号管理`。

# 12. 消息气泡

## Text

- 自己与对方明显区分。
- 桌面/移动字体和最大宽度合理。
- 不拉到整屏巨宽。
- URL/Mention 等实体可点击。
- 消息内 `http://` / `https://` 链接使用蓝色语义文本；每条文本消息最多自动展示一个首链接预览卡，预览包含站点、标题、摘要等安全元数据；点击链接文字或预览卡统一交给系统默认浏览器/外部处理器，不在 DD 内嵌不受控 WebView。
- 链接预览由 DD 服务端代理抓取，不允许客户端绕过服务端直接拉取任意页面；服务端必须拦截私网/回环/链路本地地址、危险端口和不安全重定向，限制响应大小与超时，避免 SSRF 与资源放大。

## System

居中、弱化，不用普通聊天气泡。

## Media

图片/GIF/Sticker/Video 使用真实媒体卡片，不显示：

```text
[图片]
[GIF]
[表情]
[视频]
```

作为正常最终视觉。

只有媒体损坏/缺失时显示明确 fallback。

Sticker 与普通图片必须是两套聊天缩略图规格，不能只因为底层都是媒体就渲染成同样大小：

- 普通图片继续按图片比例与图片卡片约束展示；
- Sticker 保持完整比例 `contain`，不使用图片式 `cover` 裁切；
- 移动端 Sticker 最大边约 `176px`，桌面内嵌聊天最大边约 `220px`，必须明显小于普通图片卡片；
- Sticker 不套普通图片的圆角裁切外观，表情归表情、图片归图片。

# 13. 消息操作菜单

### Mobile

使用统一 `DdActionSheet`。

- 点击菜单外任意遮罩/聊天空白区域必须立即关闭菜单，不执行任何动作。
- Android 系统返回键与下滑关闭继续保留，不能出现“打开后只能选一项才能退出”的死路。
- 透明布局层不得吞掉菜单外点击；即使 ActionSheet 为了长列表使用可滚动高度限制，也必须有显式 dismiss hit layer 兜底。

### Windows

右键菜单风格参考 Telegram 的紧凑、干净，但用 DD token。

当前操作：

- 回复。
- 复制（TEXT only）。
- 转发。
- 对方发送且当前仍可见的 Sticker：`添加到我的表情`。
- 收藏。
- 置顶消息。
- 编辑（自己的 TEXT）。
- 撤回（自己的消息）。
- 仅本地删除（红色）。

媒体消息禁止显示没有意义的“复制”。

收到的 Sticker 允许长按/右键直接加入自己的自定义表情库；服务端只能接受当前用户自己拥有，或当前用户作为活跃会话成员仍能看到、未撤回、未被本地删除的 `STICKER` 消息媒体，不能通过猜 `mediaId` 收藏任意他人媒体。

当前代码已通过 `_canCopyMessage` 与 Sticker 媒体授权边界限制上述行为。

# 14. 输入区

基本：

```text
语音 | 输入框 | Emoji | 更多/发送
```

状态转换：

- 空输入时显示附件/语音等。
- 有文本时发送操作明显。
- Emoji/Sticker panel 与键盘互切自然。

Windows：

```text
Enter      发送
Shift+Enter 换行
```

Android 外接键盘/scrcpy：Enter 也应发送。

群聊（Windows / Android / Web 等现有客户端统一）：

- 无进行中群通话时，输入框上方**不常驻“发起群通话”横条**。
- 群语音/群视频的发起入口统一收进 `+` 更多菜单，和相册、拍摄、文件属于同一附件动作区；桌面端不得再退回输入框上方常驻入口。
- 只有检测到**进行中的群通话**时，才允许在输入区上方显示紧凑的“加入群通话”状态入口，避免用户错过正在进行的通话。

发送后保持输入焦点。

# 15. 键盘体验

Windows：

- `Esc` 作为统一“返回上一层”快捷键：当前存在可返回的二级 `Navigator` 页面、详情页或弹层时，触发 `maybePop` 返回上一层。
- 页面内部已经定义更具体的 `Esc` 行为时优先处理局部状态，例如 Mention 候选先关闭、视频全屏先退出全屏，不能被全局返回抢占。
- 已处于主导航根层时，`Esc` 不退出程序、不缩到托盘，也不在“消息 / 联系人 / 发现 / 我的”四个一级入口之间乱跳。

Android：

- 键盘升起时消息区跟随，不明显跳帧。
- 键盘落下不整页闪烁。
- 点击空白合理 dismiss。
- Footer 在键盘可见时不抢占底部空间。
- Mention tap 后保持输入焦点。

性能排查：

- 避免根 Scaffold 每帧大 rebuild。
- 避免动画中做磁盘/网络同步阻塞。
- 图片 decode 放到合理尺寸。

# 16. Pending 消息

发送操作必须先给用户即时反馈：

```text
sending
failed
sent
```

失败消息操作：

- 立即重试。
- 取消发送（危险）。

媒体上传也应有：

- 进度。
- 取消。
- 重试。

图片/视频发送采用 **消息流内乐观缩略图**，不再在 Composer 上方额外堆横向传输条：

- 用户选中图片/视频后立即在“我”的消息位置生成本地缩略图占位；
- 上传进度以缩略图中央的圆环表示，圆环中心提供取消按钮；
- 图片直接使用本地处理后的缩略图，不等服务器回读；
- 视频 probe 完成后直接使用本地文件作为缩略图内播放源；Android 当前会在该条视频位于可视区域时静音循环自动播放，同时网络上传继续进行；
- 上传完成后乐观缩略图由正式消息替换；取消后该乐观缩略图消失；失败态在缩略图上提供重试/关闭；
- FILE/VOICE 等非视觉传输可继续使用紧凑传输条，不与图片/视频视觉发送混用。

取消必须真的中断 transport。

# 24. Emoji / Sticker 面板

统一 Emoji 按钮打开：

```text
Emoji
自定义 Sticker
Telegram Packs
```

发现页不再显示占位性质的“更多能力”；改为正式 `表情` 入口。该入口打开表情管理视图，可查看/整理自定义 Sticker，并管理已导入 Telegram Packs（导入、移除、分享等）；聊天输入区的 Emoji 按钮继续用于选择并发送表情。

要求：

- 大列表可滚动。
- 不 overflow。
- 动态 Sticker/GIF 只对可见项播放/解码。
- 失败 item 有明确占位，而不是整个库白屏。
- Telegram 表情包整包分享卡必须展示该包排序第一项的真实表情缩略图，不允许长期使用通用图标代替；接收方在尚未添加该包时也必须能看到缩略图并点击导入，转发后继续保留该预览与导入能力。

# 29. 通知

## Foreground

顶部应用内 banner：

- 头像。
- 名称。
- 摘要。
- Mention 标题。

通知摘要必须是用户可读文案，禁止泄露协议/枚举标签，例如 `[STICKER]`、`[IMAGE]`、`[VIDEO]`。媒体消息统一使用 `贴纸`、`图片`、`GIF`、`视频`、`语音消息`、`文件` 等语义摘要；未知类型回退为 `新消息`，不能把内部类型名直接拼进 UI。

不在底部弹通知。

## Transient Feedback / Toast / SnackBar

收藏、复制、保存、失败等短反馈统一遵循：

- 全局使用 floating 行为，不贴屏幕最底边；
- 底部至少预留 88px 持久控件安全区，覆盖 Android 悬浮 Footer 与聊天输入框常规高度；
- 不允许覆盖聊天输入框、Footer、Bottom Action、确认/取消等底部交互控件；
- 页面不得通过自定义 `margin` / `fixed SnackBar` 绕过全局安全区；
- 需要业务级前台通知时仍走顶部应用内 banner，不用底部黑条代替。

## Android Background

- Heads-up。
- DD monochrome small icon。
- sender avatar large icon。
- channel 版本化处理历史低优先级。
- 后台 Push 与前台 banner 使用同一套“用户可读媒体摘要”规则，不得出现带方括号的内部消息类型标签。

## Windows

优先 DD 自定义通知 popup；失败 fallback Windows system toast。

# 33. Moments UI

P8 已接入“发现 → 朋友圈”。体验基线：

- Feed 头像/昵称/时间/正文层级接近微信信息密度，不做瀑布流社交媒体；
- 最多 9 图使用规则网格；单视频必须先显示真实 poster，不允许长期停在黑色“视频”占位；视频进入当前可视区域且可见比例达到播放阈值时静音循环自动播放，同屏只允许最可见的一条自动播放，滚出可视区/切页后暂停；单击视频直接进入完整播放器；poster probe 失败时保留可点击播放兜底；
- 发布页支持文字、图片、单视频和“谁可以看”；
- 点赞/评论操作轻量，不用满屏弹窗；
- 别人点赞、评论我的朋友圈，或回复我的朋友圈评论后，“发现”Footer/桌面 Rail 与“发现 → 朋友圈”行必须同步显示红色数字未读角标；1～99 显示真实数字，100 及以上统一显示 `99+`，不能只弹一次通知然后丢失状态；
- 自己的朋友圈封面下方固定保留“互动焦点”：最多叠放 3 个最近互动头像；有未读时显示 `N 条新互动` 与红色数字，已读后显示“最近互动”；摘要直接说明“某某赞了你的朋友圈 / 某某评论了你：正文”。点击后打开互动消息面板，逐条显示头像、昵称、点赞/评论正文和相对时间；不允许清未读时把历史互动一起清掉；
- 角标事实来自服务端持久互动未读状态，Realtime/Push 只负责催刷新；App 重启、从后台恢复或漏收 Push 后应主动重新拉取；进入自己的朋友圈时立即清除当前角标并向服务端标记已读；

- Feed 媒体按可见区域加载，避免打开页面就预拉全量视频；
- 权限失败显示正常业务提示，不泄露 Block/不可见具体原因。

# 35. Empty / Loading / Error

所有页面必须区分：

```text
loading
empty
error
content
```

禁止：

- 网络 500 → 显示“用户已删除”。
- Sticker provider 错误 → 整页无限 loading。
- 视频解码失败 → 把消息当普通 `[视频]` 文本长期展示。
- Token refresh timeout → 自动登出。

# 36. 动画标准

原则：快、克制、不晃。

典型：

- 120～220ms 小 UI 切换。
- easeOutCubic 类快速结束曲线。
- 避免大面积 opacity animation 造成整屏 flash。
- 动画过程中不触发重 IO。

真实体验高于“用了多少动画”。

- 点击区域 >= 合理移动触控尺寸。

- Semantics 给主要按钮/导航。
- 深色模式对比度。
- 不能只靠颜色表达危险/选中。
