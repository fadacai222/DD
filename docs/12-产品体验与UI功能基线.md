# DD 产品体验与 UI 功能基线

> 更新时间：2026-08-11（朋友圈/二维码/正式通话 UI 状态同步）
>
> 核心口径：**微信式信息层级 + Telegram 式功能开放性、性能与流畅度 + DD 自有品牌资产。**

---

# 1. 体验北极星

用户不应该感觉自己在使用“Flutter 工程 Demo”。

目标：

- 页面打开快。
- 输入立即响应。
- 消息立即出现 pending 状态。
- 媒体看过后快速再次打开。
- 导航和键盘动画稳定。
- 不反复弹技术错误码。
- 所有入口与状态符合常见 IM 心智。

---

# 2. 参考边界

## 2.1 参考微信

- 四主入口信息架构。
- 聊天/联系人/我的层级。
- 联系人默认列表。
- 克制的消息气泡与列表密度。
- 资料页从身份到操作的层级。
- 危险操作红色。

## 2.2 参考 Telegram

- 多端同步。
- 消息编辑。
- 不限微信式 2 分钟撤回。
- 转发、收藏、置顶、搜索。
- Sticker/GIF/媒体开放性。
- 本地缓存与快速二次打开。
- Desktop 信息密度。
- 动画反馈迅速。

## 2.3 不参考

- 不以 WhatsApp 的视觉与菜单作为设计方向。
- 不复制微信/Telegram logo、通知音、表情资产、品牌 icon。
- 不复制第三方专有布局像素到侵权程度；使用 DD 自己 token 和资产重做。

# 4. Android 悬浮 Footer

当前使用：

```text
DdFloatingNavigationBar
```

产品方向：

- 全圆角悬浮 pill。
- 与屏幕左右/底部留空间。
- 选中项有轻量背景 indicator。
- 图标 + 小标签。
- 使用 DD 绿色强调色。

实现要求：

- 整个 Footer 不能每次切 Tab fade-out/fade-in。
- 只动画 selection indicator/必要属性。
- `RepaintBoundary` 隔离重绘。
- 快速点击以最后一次选择为准。
- 键盘出现时合理隐藏，避免和输入框争高度。

当前历史真人问题：快速切换闪烁。

当前代码已换为稳定 Stateless tree + `AnimatedPositioned` indicator，状态：


# 12. 消息气泡

## Text

- 自己与对方明显区分。
- 桌面/移动字体和最大宽度合理。
- 不拉到整屏巨宽。
- URL/Mention 等实体可点击。

## System

居中、弱化，不用普通聊天气泡。

## Media

图片/GIF/Sticker/Video 使用真实媒体卡片，不显示：

```text
[图片]
[GIF]
[表情]
[视频]
```

作为正常最终视觉。

只有媒体损坏/缺失时显示明确 fallback。

### Mobile

使用统一 `DdActionSheet`。

### Windows

右键菜单风格参考 Telegram 的紧凑、干净，但用 DD token。

- 转发。
- 收藏。
- 置顶消息。
- 编辑（自己的 TEXT）。

# 14. 输入区

基本：

```text
语音 | 输入框 | Emoji | 更多/发送
```

状态转换：

- 空输入时显示附件/语音等。
- 有文本时发送操作明显。
- Emoji/Sticker panel 与键盘互切自然。

Windows：

```text

Shift+Enter 换行
```

Android 外接键盘/scrcpy：Enter 也应发送。

发送后保持输入焦点。

# 15. 键盘体验

Android：

- 键盘升起时消息区跟随，不明显跳帧。
- 键盘落下不整页闪烁。
- 点击空白合理 dismiss。
- Footer 在键盘可见时不抢占底部空间。
- Mention tap 后保持输入焦点。

性能排查：

- 避免根 Scaffold 每帧大 rebuild。
- 避免动画中做磁盘/网络同步阻塞。
- 图片 decode 放到合理尺寸。

# 16. Pending 消息

发送操作必须先给用户即时反馈：

```text
sending
failed
sent
```

失败消息操作：

- 立即重试。
- 取消发送（危险）。

媒体上传也应有：

- 进度。
- 取消。
- 重试。

取消必须真的中断 transport。

# 17. 回复

回复编辑区在 composer 上方显示引用。

消息内引用：

- 昵称/摘要。
- 点击定位源消息。
- 如果源消息在旧分页，先加载旧页再定位。
- 定位后短暂高亮。

# 18. 编辑

自己的 TEXT：

- “编辑”菜单。
- Composer 进入编辑态。
- 明确取消/提交。
- 服务端 version conflict 显示可理解提示。
- 编辑后气泡显示“已编辑”或相应弱提示。

---

# 19. 撤回

自己的消息默认不限制 2 分钟。

撤回后：

- 所有设备同步。
- 气泡变 system-like recalled state。
- 媒体内容不继续可打开。

不要只在当前客户端本地把 widget 隐藏。

---

# 20. 收藏 / Saved Messages

“收藏”入口最终体验优先向 Telegram Saved Messages 靠拢：

```text

```

当前 SELF 会话可：

- 自己给自己发文字/媒体。
- 跨设备同步。
- 保存重要消息。

传统 bookmark list 保留兼容，但不要长期维护两套完全分裂的产品心智。

# 25. Attachment Sheet

当前附件入口应整合：

- 相册（图片/GIF/视频）。

# 33. Moments UI

P8 已接入“发现 → 朋友圈”。体验基线：

- Feed 头像/昵称/时间/正文层级接近微信信息密度，不做瀑布流社交媒体；
- 最多 9 图使用规则网格；单视频显示 poster + 播放入口；
- 发布页支持文字、图片、单视频和“谁可以看”；
- 点赞/评论操作轻量，不用满屏弹窗；
- 隐私选项必须明确区分“部分可见 / 不给谁看 / 长期不看他 / 不让他看”；
- Feed 媒体按可见区域加载，避免打开页面就预拉全量视频；
- 权限失败显示正常业务提示，不泄露 Block/不可见具体原因。

状态：`IMPLEMENTED + AUTO-VERIFIED / HUMAN-PENDING`。

# 34. QR UI

P9 当前已写：我的二维码、群二维码、扫一扫、PC/Web 扫码登录页面。

体验规则：

- 个人码清楚显示 DD 身份与实例归属；
- 扫到登录码后，手机确认页必须显示**服务端返回**的目标设备名称/平台，不信任二维码自带文案；
- 群二维码页面给 Owner/Admin 明确的有效期/撤销操作；
- Windows 不假装有 `mobile_scanner` 摄像头能力，提供手动粘贴/解析 payload 兜底；
- 外实例 payload 必须提示不属于当前实例；
- reject/expired/consumed 使用可理解状态，不展示裸 SQL/HTTP 异常。

当前 Flutter QR 门禁为 `KNOWN-FAILURE`，在 analyzer/test/build 修复前，这些页面不能标发布可用。

# 35. Empty / Loading / Error

所有页面必须区分：

```text
loading
empty
error
content
```

禁止：

- 网络 500 → 显示“用户已删除”。
- Sticker provider 错误 → 整页无限 loading。
- 视频解码失败 → 把消息当普通 `[视频]` 文本长期展示。
- Token refresh timeout → 自动登出。

---

# 36. 动画标准

原则：快、克制、不晃。

典型：

- 120～220ms 小 UI 切换。
- easeOutCubic 类快速结束曲线。
- 避免大面积 opacity animation 造成整屏 flash。
- 动画过程中不触发重 IO。

真实体验高于“用了多少动画”。

---

# 37. 可访问性

- 点击区域 >= 合理移动触控尺寸。
- 文字随系统缩放有上限策略，避免 Footer 崩坏。
- Semantics 给主要按钮/导航。
- 深色模式对比度。
- 不能只靠颜色表达危险/选中。

---

全部来自真人测试，不允许仅靠 Widget Test 抹掉。
